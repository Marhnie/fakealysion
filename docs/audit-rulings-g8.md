## 확인 완료 — 이미 올바르게 구현되어 있음 (버그 아님)

- **DP가 0이 된 디지몬은 다단계 효과 도중 즉시 소멸하지 않고, 효과 전체(또는 사용한 옵션 카드 파기/아츠 진화 완료) 후 룰체크로 일괄 소멸** (ST24-06/07/09/10 라이즈그레이몬 계열, P-172/186/191 등 다수, id 6166/6213/6215/4629/4421 등): `state.js`의 `flushRuleChecks`가 "룰 체크는 효과 처리 중(`runScript` depth>0)에는 수행하지 않고 가장 바깥 효과가 끝난 뒤 한 번에 수행"함을 확인(`17-1-2-2` 인용 주석 존재). 이미 정확히 구현됨.
- **"N마리를 소멸시킨다"류 강제 효과는 대상이 있으면 반드시 선택해야 한다** (ST7-09 듀크몬, P-186 듀크몬 등, id 690/4629): `effects.js`의 `wrapChoose`가 `ctx.trigger.text`에 "수 있다/까지/없어도/않아도/않을 수" 패턴이 없으면 `payload.required=true`로 강제해 UI의 "대상 없음/취소" 버튼을 숨김을 확인.

- **동시에 소멸한 디지몬은 자신의 진화원 효과("상대 디지몬이 소멸했을 때")가 발동하지 않는다** (ST7-03 길몬, ST7-05 그라우몬, id 681/683): 트리거 발동 전에 이미 배틀 에어리어를 벗어난 상태라 `emitGameEvent`의 holder 순회에서 제외됨을 확인.

## 의심되지만 확정하지 못한 것 (suspicious but unresolved)

- **≪연계≫ 강제 부여가 UI 상에서 "취소" 가능하게 노출될 수 있음** (ST20-04/06/09 가루다몬 등 3장, ST21-04/06/09 지가모드 등 3장, id 4445/4448/4453/4472/4475/4479 — "다른 자신의 어드벤처 디지몬이 등장/진화했을 때, 자신의 디지몬 1마리는 ≪연계≫를 얻는다. 그 후, 자신의 디지몬 1마리로 어택할 수 있다"): 공식 룰링은 "≪연계≫ 부여는 반드시 해야 하며 발휘하지 않기를 선택할 수 없다"고 명시하나, 이 두 문장이 **하나의 트리거 텍스트**로 큐잉되어(`src/state.js`의 `parseWatcherTrigger`/`emitGameEvent`, `Q4693 family` 주석 확인 — 조건부 게이팅 자체는 정확히 처리됨) `ctx.trigger.text`에 뒤 문장의 "할 수 있다"가 포함된 채로 `grantKeyword`의 대상 선택(`ctx.choose('pickStack', ...)`)까지 함께 처리된다. `wrapChoose`의 필수 판정이 **트리거 전체 텍스트 단위**라서, 이론상 사람이 조작하는 UI에서 ≪연계≫ 부여 대상 선택에도 "대상 없음/취소" 버튼이 노출될 수 있다(실제로 스크래치 스크립트로 `grantKeyword`의 `ctx.choose` 호출에 `payload.required=false`가 전달됨을 확인). 다만: (1) CPU AI(`src/cpu.js`)는 "부여" 동사가 `GOOD_VERB`로 분류되어 `required` 값과 무관하게 항상 대상을 고르므로 CPU 대전에는 영향이 없고, (2) 사람도 무료 키워드 부여를 합리적으로 거부할 이유가 없어 실질적 게임 결과에 영향은 미미할 것으로 판단된다. 다만 이 문제의 근본 원인(`wrapChoose`가 세그먼트 전체 텍스트 단위로만 필수 여부를 판정)은 "선택적 절 뒤에 강제 절이 없는" 다른 카드에도 잠재할 수 있는 **제네릭 아키텍처 한계**로, 7개 형제 에이전트가 `effects.js`/`state.js`를 동시에 편집 중인 상황에서 이 휴리스틱 자체를 손대는 것은 회귀 위험이 크다고 판단해 이번에는 보수적으로 손대지 않고 여기 기록만 남긴다. (문장 단위로 절을 쪼개 각 op에 원본 절 텍스트를 붙여야 근본 해결 가능 — 후속 작업 권장.)
- **"이 디지몬의 진화원 색상 1개마다 DP+1000" 등에서 진화원이 여러 장 겹친 하위 스택의 색은 최상단 카드 색만 카운트되는지** (ST9-11 다이노몬, id 731 — "이 진화원 효과는 진화원 카드의 색도 셀 수 있는가?" → "아니오, 가장 위 카드의 색만 센다"): 코드상 `sources` 배열이 평탄화된 카드 ID 리스트라 "겹친 하위 스택" 개념 자체가 있는지, 있다면 정확히 최상단만 세는지 실제 조그레스+추가 진화 시나리오로 재현 검증하지 못했다.
