# CPU 덱 빌딩 AI — 진화 학습 리포트

구성 파일
- `src/cpudeck.js` — 순수 로직(브라우저/Node 공용): 합법 덱 생성기, 진화 연산자(교차/변이), 런타임 API.
- `scripts/evolve-decks.mjs` — **오프라인** 진화 트레이너(Node, `worker_threads` 병렬). 결과만 `data/cpu-decks.json`(카드 id + 장수, 카드 텍스트 없음, 약 12KB)로 출하. 브라우저는 학습하지 않고 이 JSON 을 읽기만 한다.
- `scripts/test-cpudeck.mjs` — 출하 덱 전부의 합법성 + 생성기 300 시드 합법성 + 런타임 API 테스트(전부 OK).
- 학습 로그 원본: 스크래치패드 `run1/evolve-log.txt`, 상태(재개용) `run1/evolve-state.json`.

## 1. 방법

### 1.1 합법 덱 생성기 (`genGenome` → `compile`)
1. 1~2색 선택(단색 7 + 2색 21 = 28개 색 조합을 라운드로빈으로 초기 인구에 골고루 배치).
2. **진화 라인(LINE)** 을 3~4개 만든다: 디지타마(Lv.2) → Lv.3 → Lv.4 → Lv.5 (→ Lv.6). 다음 단계 후보는 `E.canEvolveAny` 로 실제 진화 조건(레벨/색/이름/특징 조건)을 만족하는 카드만 고른다 = 게임이 쓰는 코드 그대로. 라인당 복사수 목표 Lv3 4~5 / Lv4 3~4 / Lv5 2~3 / Lv6 1~2.
3. 서포트: 테이머 1~2종(3~5장) + 옵션 2~4종(4~8장). 옵션은 4-22 색 조건을 위해 같은 색 디지몬/테이머가 6장 이상 있어야만 남긴다.
4. 50장 맞추기: 초과 시 필러 → 서포트 → 두꺼운 라인 순으로 제거, 부족 시 Lv3/4 라인 노드 증량 → 라인 카드의 진화 후보 추가 → 서포트 추가. 디지타마덱은 3~5장(목표 4~5), 이 덱의 Lv.3 로 실제 진화할 수 있는 것만.
5. 제외: 토큰/패러렐/`docs/manual-effects.md` 의 수동 fallback 효과 카드 103장(파일에서 파싱, `data/cpu-decks.json` 의 `avoid` 로 함께 출하).
6. 검증: `S.deckLegality`(50장/≤4장·별칭 합산/디지타마 규칙) + `decktools.deckCheckup` 의 error 등급 0건.

genome = `{colors, lines:[{egg, nodes[{id,n,lv}]}], support[], extra[]}` (`extra` 는 랜덤 필러를 기록해서 번식이 결정적이도록 `syncGenome` 으로 컴파일 결과와 동기화).

생성기 통계(300 시드, 전부 합법·체크업 error 0): 평균 Lv3 14.6 / Lv4 12.7 / Lv5 9.2 / Lv6 3.5 / 테이머 3.9 / 옵션 6.1 / 디지타마 4.6.

### 1.2 적합도 (fitness)
- 헤드리스 CPU 대 CPU 실전(`src/cpusim.js`, 실제 엔진). 승 = 1, 무 = 0.5. **모든 대진을 선공 1회 + 후공 1회**.
- 게임 시드는 (세대, 후보, 상대)로 결정 → 재현 가능. 세대 내 모든 후보가 **같은 상대 집합**을 만난다(짝지은 비교).
- CPU 레벨: 전체 예산의 앞 30%(gen 0~5)는 `normal`(속도), 이후 `hard`(탐색 없는 휴리스틱 hard). 최종 재평가/검증은 전부 `hard`.
- 건틀릿(세대마다 새로 샘플): 스타터 덱 6종(21종 중) + 「사람이 짠 듯한」 베이스라인 4종(12종 중; 랜덤 코히런트 6 + 진화 체인 테마 6, 시드 777 고정) + 명예의 전당(HOF) 최대 5종. 스타터 덱은 데이터에 리스트가 없어 ST 카드 + 같은 색 보충으로 합법 50장 구성(`cpu-hunt.mjs genStarter` 와 동일 방식).
- 개체 적합도 = 이번 세대 승률과 이전 값의 지수 이동평균(0.5/0.5) → 운 좋은 1회에 엘리트가 고착되는 것을 완화.

### 1.3 진화 탐색
- 인구 **32**, 세대당 개체당 약 60판(대진 15 x 선/후공 2 x reps 2), 세대당 약 1,900판.
- 토너먼트 선택(크기 3), 적합도 - 0.02 x (같은 색 조합 안 순위) = **다양성 압력**(한 색으로 몰리는 것 방지).
- 교차: 부모 라인(색 패키지)을 통째로 교환(라인 2~4개, 색이 다르면 두 색의 합집합이 2색 이하일 때만 합침, 서포트는 한쪽 부모 것 + 확률적 병합).
- 변이(1~3개): 라인 내 카드 교체(전/후 진화 가능성 유지) / 복사수 ±1 / 라인 통째 재생성 / 라인 추가·삭제 / Lv6 연장·Lv5 자르기 / 서포트 교체 / 필러 재추첨 / 디지타마 교체 / **색 패키지 변경**.
- 엘리트: 상위 4 + 색 조합별 최고(최대 인구의 1/3), 이민자 12%(개체수가 적은 색 조합 위주로 새 생성), 중복 덱 해시 금지.
- HOF: 세대 챔피언(+4세대마다 색 조합별 챔피언), 최대 12, 다음 세대부터 건틀릿에 포함(자기 자신과는 대전 안 함).
- 색 조합별 아카이브 상위 8. 재개 가능한 상태 파일(`--resume`, 세대별 시드 재유도).

### 1.4 마무리(finalize) 와 내보내기
- 아카이브(색 조합별 3) + HOF + 마지막 인구 = 114개 후보를 **전체 건틀릿**(스타터 21 + 베이스라인 12 + HOF 12 = 45종)과 `hard` 로 재평가: 1단계 90판 -> 색 조합별 상위 4개(93개)는 180판 추가(총 270판, 새 시드).
- 색 조합별 승률 상위 N=3 (승률 >= 50%, 체크업 통과) 를 `data/cpu-decks.json` 에 `{name, colors, main, digitama, winrate, games, generation}` 로 출력(총 28개덱, 12개 색 조합).

## 2. 학습 실행

- 실행: N = 32 개체, 시드 `--seed 1`, 총 36세대, 학습 27.5분(12.2분 실행 + `--resume` 로 이어서 15.3분; 첫 실행의 시간 계산 버그로 절반에서 끝나 재개함), 약 6.6만 판(세대당 ~1,900판, 12코어에서 세대당 30~60초).

## 4. 런타임 API (`src/cpudeck.js`)

- `await loadCpuDecks(url='./data/cpu-decks.json')` — 출하 덱 로드(+ `avoid` 반영, 강한 덱에 등장하는 카드에 소폭 학습 보너스 `LEARNED`).
- `pickCpuDeck({colors?, style?, rng?})` — `colors` 허용 색(덱 색이 그 부분집합), `style` = `strong`(승률 가중 소프트맥스, 기본) / `random` / `aggro` / `midrange` / `ramp` / `control`(덱 구성에서 계산). `S.newGame` 에 바로 넣을 수 있는 `{name, main, digitama, colors, winrate…}` 반환.
- `buildDeckFromCollection({owned?, sets?, allow?, colors?, rng?, tries?})` — 「CPU가 내 카드로 덱 추천」. `owned`=`{id:장수}` 소지 카드, `sets`=`['BT1','ST3']` 카드 번호 접두(세트 풀), `allow`=카드 술어. (1) 출하 진화 덱이 풀 안에 완전히 들어가면 그대로 추천, (2) 아니면 그 풀로 라인 생성 + 정적 점수(카드 prior + Lv 곡선 적합 + 구조 패널티) 기준 60회 생성 x 6회 힐클라임, 결과는 합법 + 체크업 통과. 풀이 부족하면 `{ok:false, reason}`. 시뮬레이션 없이 폰에서 수백 ms~수 초.
- 저수준: `genGenome/compile/mutate/crossover/syncGenome/checkDeck/deckStyle/staticScore/setAvoid`.
- UI 연결(덱 빌더 버튼 / vs CPU 시 덱 선택)은 이번 범위에 포함하지 않았다(API 만 제공). `main.js` 통합은 후속 작업.

## 5. 한계 / 후속

- **CPU 플레이에 과적합**: 적합도가 「이 엔진의 hard CPU 가 굴렸을 때」의 승률이다. 진화 결과가 테이머/옵션 거의 없는 Lv5/Lv6 편중(평균 Lv5 14.6, Lv6 6.5, 테이머 2, 옵션 2.8) + 레드 라인으로 수렴 -> CPU 가 옵션/테이머를 잘 못 쓰고(낭비 액션) 큰 디지몬 진화 러시가 유리하다는 엔진 특성을 반영. 사람이 쓰기엔 어색할 수 있다(생성기 자체는 테이머/옵션 3~10장 구조).
- 다양성: 다양성 압력에도 인구는 레드 계열(레드/레드-블랙/레드-그린)로 수렴, 블루·옐로·퍼플·블랙 단색 등은 50% 이상 덱이 적거나 없음(그 색은 초기 인구에서 스타터·베이스라인에 못 이김). 색 조합별 세부 최적화는 더 긴 학습/색별 개별 인구가 필요.
- 노이즈/선택 편향: 세대당 개체당 ~60판(SE ≈ 6%)이라 세대 곡선이 흔들림. 출하 승률은 선택 후 새 시드 270판 재평가이지만 색 조합별 상위 4개 중 3개를 고른 최선값이라 약간 낙관적(검증표의 「vs 스타터」 새 시드 결과가 실제 기대치에 가깝다).
- 건틀릿의 「스타터」는 실제 스타터 리스트가 아니라 ST 카드 + 랜덤 보충이라 실제 스타터보다 약하다(진화 덱 vs 스타터 73% 는 그 점을 감안해야 함). 「사람 저장 덱」 스타일 기준선도 랜덤/체인 생성 덱(메타 덱 아님).
- 총 학습 27.5분/약 6.6만 판이며 hard 는 탐색(hard4) 없는 버전이다. 사용자가 실제로 마주치는 hard4 로 재학습하면 결과가 달라질 수 있다.
- 다음 단계 제안: (1) 테이머/옵션 최소 장수 제약 또는 인간 선호 보정, (2) 색별 개별 인구, (3) 실제 스타터/메타 덱 리스트 입력, (4) `main.js` 에 CPU 덱 선택/추천 UI 연결.

재현
```
node scripts/evolve-decks.mjs --mode evolve --minutes 27 --pop 32 --seed 1 --reps 2 --scratch <dir> --out data/cpu-decks.json < /dev/null   # (--resume 으로 이어서)
node scripts/evolve-decks.mjs --mode verify --n 400 --top 12 --scratch <dir> --state <dir>/evolve-state.json < /dev/null
node scripts/test-cpudeck.mjs < /dev/null
```
