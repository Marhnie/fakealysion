# UI 장기전 플레이테스트 리포트 (CPU 대전, 후반전/복합 메커니즘 중심)

도구: `scripts/uilong.js` (uibot 위에 얹은 장기전 하네스 — LG.mkDeck / LG.game / LG.fplay: 랜덤 모달 응답, 특수 카드 주입, 카드 보존 검사, 스톨 감지),
격리된 Edge(headless, CDP)에서 실행. 각 항목: 상황 → 기대 → 실제 → 원인 → 수정/보류.

## 1. CPU가 무효 【메인】 효과를 한 턴에 20회 이상 반복 (수정)
- 상황: CPU(P2)가 곽소룡(ST17-10)을 배틀 에어리어에 두고 있고 테리어몬/세인트가르고몬이 없는 상태에서 자기 턴 메인 페이즈.
- 기대: 효과가 아무 일도 못 하면 한 번 시도하고 다음 행동으로 넘어감.
- 실제: 로그에 `🤖 CPU: 【메인】 효과 사용`이 22번 연속, 턴이 약 3분 걸림 (액션 상한 45에 가까워야 패스).
- 원인: `mainAbilityPayable`이 이 카드에 대해 true를 반환(비용 그룹으로 컴파일되지 않음) + `execute()`의 "전후 시그니처 동일 → 밴" 검사는 `useMain`이 pending 행을 즉시 push하므로 항상 다르게 보여 발동하지 않음.
- 수정: `src/cpu.js` execute 'main' — 같은 【메인】 키는 턴당 2회까지만 (`D.mainUses`, 턴 키 바뀌면 리셋).

## 2. 효과로 얻은 어택에 대상이 없으면 버튼 없는 어택 창에서 소프트락 (수정)
- 상황: 다이노몬(BT12-055) 조그레스 진화 → 【진화 시】 "…이 디지몬으로 상대의 디지몬에게 어택할 수 있다." 상대 필드에 레스트 디지몬이 없음(플레이어 직접 공격 불가 제약).
- 기대: 어택 가능한 대상이 없으면 어택이 선언되지 않고 효과가 끝남.
- 실제: `공격 선언` 로그 후 어택 창이 뜨는데 "플레이어에게 어택할 수 없음 / 대상이 될 디지몬이 없음" 문구뿐 **버튼이 하나도 없어** 게임이 멈춤 (턴 종료·패스 모두 "해결 중인 처리가 남아 있어…"로 거절).
- 원인: `attackFlow(force=true)` (효과가 여는 어택)은 `declareAttack` 이후에야 대상을 계산하고, targetChoice 단계에 대상이 0개일 때의 출구가 없었음.
- 수정: `src/main.js` attackFlow — force일 때 선언 전에 합법 대상(디지몬/플레이어)을 확인해 없으면 로그만 남기고 종료; targetChoice에 대상이 전혀 없으면 "어택 종료 (대상 없음)" 버튼 추가(안전망).

## 3. 새로고침/이어하기가 "그 턴의 시작"으로만 복원 (수정, 개선)
- 상황: 메인 페이즈에서 카드 2장 등장 후 새로고침 → "▶ 마지막 게임 이어하기".
- 기대: 마지막 안정 지점(진행한 액션 포함)에서 이어짐.
- 실제: 자동 저장이 "턴당 1회(턴 첫 안정 렌더)"뿐이라 그 턴에 한 액션이 전부 사라짐 (긴 후반전 턴일수록 손실 큼). 저장 자체는 1 ms/32 KB로 저렴.
- 수정: `src/practice.js` afterRender — 안정 지점에서 4초 이상 지나고 상태 digest가 바뀌었으면 auto 슬롯도 갱신. 검증: 등장 2회 → 새로고침 → 이어하기: 손패/배틀/메모리 그대로 복원.

## 4. 검증 요약 (버그 없음 확인)
- 조그레스: 조그레스 카드 72종 전부 UI 경로(핸드 → 재료 드롭 → 모달 → 짝 선택)로 실행 — 결과 스택 존재, 진화원 ≥2, 메모리 = 10 − 코스트, 후속 프롬프트 랜덤 응답 후 소프트락 없음 (#2 수정 후 72/72).
- 옵션 카드 약 150종(【메인】/딜레이 포함) 무작위 보드에서 UI로 사용: JS 에러/소프트락/카드 보존 위반 없음.
- 【시큐리티】 효과 240종: 상대 어택 → 시큐리티 체크 → 효과 프롬프트 랜덤 응답. 카드 보존 불일치 9건 중 석화 토큰(TOKEN-석화) 생성 때문에 +1이 되는 경우 제외하면 EX1-068 1건(120회 중 1회, p2 트래시 -1, 로그 없음)만 재현되었으나 하네스의 이전 반복 잔여 비동기와 구분되지 않아 **보류(미확정)**.
- 성능(양쪽 12스택×진화원 6, 트래시 45, 핸드 20, 로그 300): render() 중앙값 19 ms, DOM 462, 카드 선택 클릭 27–41 ms, 세이브 1 ms/32 KB.
- 폰(375×812): 가로 스크롤 없음, 33개 카드 칩 모두 elementFromPoint 가림 없음, 탭만으로 등장/공격 대상 선택(본체/디지몬) 가능.
- 되돌리기/다시: 등장 2회 → 되돌리기 ×2 → 다시, DOM(손패/배틀 칩 수)과 상태 일치.
- 참고(비버그): 동시 발동 대기 4개(【자신의 턴 개시 시】 메모리 2 이하→3) 순서 선택창이 동일 효과 4개를 모두 물어봄 — 룰상 정확하나 마찰. 보류.

## 5. "정확히 1장 선택" 프롬프트에서 다른 카드를 누르면 "2/1장 선택됨" + 죽은 확인 (수정)
- 상황: 상대 효과로 "패 1장 파기"(ST22-14 발바몬 【자신의 턴 종료 시】 등) 선택창에서 카드 A를 누른 뒤 마음이 바뀌어 B를 누름.
- 기대: 1장 선택창에서는 B로 선택이 교체됨.
- 실제: A·B 둘 다 선택 → "2/1장 선택됨", 확인 비활성 → A를 다시 눌러 해제해야 함 (손패가 많은 후반전에서 특히 번거롭고, 자동 플레이 봇이 무작위로 누르다 40초 스톨로 판정한 케이스도 이 때문).
- 원인: `pickFromHandIndexes`(상한 없이 토글), `pickFromRevealed`(max 1도 그냥 무시), `pickSourcesMulti`(가득 차면 클릭 무시).
- 수정: `src/main.js` — n(max)==1이면 다른 카드를 누를 때 선택 교체 (3곳). 검증: 2→3번 클릭 후 "1/1장 선택됨", 확인 활성.

## 6. 하네스 관련 메모
- 격리된 Edge(CDP)에서 실행한 이유: 공용 브라우저 탭을 다른 에이전트가 새로고침/이동시켜 스크립트가 끊김.
