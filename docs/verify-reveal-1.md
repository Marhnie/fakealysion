# verify-reveal-1 (덱 오픈/탐색 카드 150 세그먼트, 배치 1)

검증 방식: `scratchpad/r1_gen.mjs` (세그먼트마다 컴파일 → 정답/오답/덱 밖 카드를 섞은 덱으로 실행, 탐욕/악의적(모든 인덱스 선택) 두 가지 chooser, 무일치 케이스: 오픈 목록 UI 표시·획득 카드·나머지 위치·덱 총량 보존을 단언, 386 케이스 0 실패) +
`r1_sp.mjs` (등장/진화/파기/진화원·테이머 아래/옵션 사용/조건 분기/비용/선택 오픈 등 개별 시나리오 80여 건 0 실패) + 실제 브라우저 1회(드라몬 오픈 → 후보 강조·선택·순서 지정 UI).

## 수정한 버그 (분류)
- **오픈 후 진화**(BT1-078, BT7-049, BT5-089): 아무 카드나 패로 가져가던 것 → `revealTop` dest 'evolve'(이 디지몬/어택한 디지몬), 진화 불가 카드는 후보에서 제외.
- **목적지 다양화**: 그룹별 dest — 패 / 파기 / 등장 / 진화 / 옵션 무료 사용 / 진화원 아래 / 「X」의 진화원 맨 아래 / 테이머 아래 / 시큐리티 위 (`routeRevealed`, `adaptRevealPick`).
- **필터 파서**: "Lv.4 또는 Lv.5"(levelAny), "Lv.5와 Lv.6 1장씩"(그룹 분리), "퍼플 또는 옐로인", "A 카드 또는 「X」 또는 「Y」"(OR), `idIn`(진화/사용 가능 후보 한정).
- **전부**: "…카드 전부"를 1장 선택으로 취급하던 것 → 조건에 맞는 카드 전부 자동, 확인 화면은 표시.
- **상대 디지몬 1마리마다**(BT3-073, BT8-068): 오픈 장수/등장 수 배수 (0마리면 오픈 안 함).
- **반환 위치**: "남은 카드는 패에 추가"(restTo hand), "덱 위/아래"(topOrBottom), 오픈만 하는 효과(`steps: []`)도 revealPick으로 표시.
- **조건 문장**: "그 카드가 …일 때/일 경우"가 상위 조건 문장으로 분리되어 오동작(P-070, ST13-02/09) → 오픈 효과 한 덩어리로 컴파일. "사용하지 않았을 때", "「X」의 진화원이 N장 이상 있을 때"는 수동 질문 대신 자동 판정.
- **비용 접두**: "…했을 때, 이 테이머를 레스트시키는 것으로"의 트리거 부분이 수동 비용이 되던 것 정리.
- **rest 대상**: 이미 레스트된 디지몬을 다시 고를 수 있어 "N마리 레스트"가 중복되던 것 방지.
- **UI**: 오픈만/무일치/dest(파기·진화·사용·진화원 아래) 문구.
- 개별 스크립트(`src/cards/shard15.js`): BT4-096, BT4-107, BT8-106, ST13-02/09, ST13-16(딜레이), BT7-004, BT10-019.

## 미해결 / 메모
- ST13-16 「덱 위 또는 아래로만」: 카드마다 위/아래를 나눌 수 있게 구현(topOrBottom). 한 쪽으로만 몰아야 하는지는 공식 문구상 불명확.
- BT10-096 「김태성」: 카드 데이터에 없음(해당 부분 검증 불가). BT3-008/062 「라그나로드몬」은 다른 조건과 배타 카드가 없어 생성 검증 제외(수동 시나리오 대상).
- 시큐리티 효과의 "이 카드를 패에 추가" 등 후속(addSelfToHand)은 기존 op 사용.
