# 레스트 없이 어택 / BT20-102 오메가몬 X항체 검증 로그

## 발견한 문제 (BT20-102)
- 전용 스크립트가 없어 범용 컴파일러가 처리 -> 【등장 시】【진화 시】는 조건 `{}`(빈 조건) + "덱 아래로 되돌린다"만 실행, "서로 1마리씩 선택 후 나머지 전부 소멸"이 통째로 누락.
- 【자신의 턴 종료 시】는 《속공》 부여만 하고 "레스트시키지 않고 어택" 문장이 누락(어택 자체가 발생하지 않음).

## 수정
1. `src/cards/shard14.js` (BT20-102 전용 스크립트)
   - 등장/진화 시: 진화원에 명칭이 「오메가몬」 또는 「X항체」(〈룰〉 명칭 취급 포함, `S.cardNameIs`)인 카드가 있을 때만 발휘(「그 후」 문장도 같은 조건문에 속함). 발휘자가 서로의 디지몬 1마리씩 선택 -> 나머지 디지몬 전부 소멸 -> 상대 디지몬 1마리 덱 아래로.
   - 자신의 턴 종료 시(턴에 1회는 엔진의 `ab.limit` 게이트 사용): 자신의 디지몬 1마리를 플레이어가 선택 -> 턴 종료까지 《속공》 부여 -> 확인 후 `startAttack(..., { noRest: true })`.
2. 범용 수정 `S.declareAttack` (`src/state.js`): 룰 11-2-1은 "레스트시켜 어택 선언"이므로 평소엔 액티브만 가능하지만, 「레스트시키지 않고 어택」은 레스트 자체를 하지 않으므로 이미 레스트 상태인 디지몬도 어택 가능 (`opts.noRest`가 `allowSuspended`를 함의). 기존 EX10-053/EX10-071이 이미 이 해석(allowSuspended)을 사용.
3. 같은 유형의 카드 전수 점검에서 발견한 개별 버그
   - BT12-083 (`s2_attackNoRest`, shard2): `attackNoRestOnce` 플래그를 아무도 읽지 않아 실제로는 레스트하고 어택 -> `{ noRest: true }`로 수정, 레스트 상태 사전 거부 제거.
   - BT21-072 (진화 시, shard5), AD1-007 (턴 종료 시, shard7), 《오버클럭》(effects.js `overclock`), `s8_attackNow`(BT26-080/086, shard8): 레스트 상태면 시도조차 안 하던 사전 검사 제거(noRest일 때만).
   - 이미 정상: EX10-053, EX10-071, BT23-070(진화 시), BT26-086/080 (declareAttack 수정으로 레스트 상태 허용).

## 검증
- Node 실제 경로: 등장 시 조건 충족 시 선택 2회 -> 나머지 소멸 -> 상대 디지몬 덱 아래(진화원 트래시), 턴 종료 시 pending 큐잉 -> 선택 -> 《속공》 부여 -> `startAttack({noRest:true})`, 레스트 상태 디지몬도 `declareAttack.ok`.
- 브라우저: 패스 -> 턴 종료 중(`state.turnEnding`)에 디지몬 선택창 -> 확인창 -> 어택 UI(대상/카운터/블록/시큐리티 체크) 정상 진행 -> 어택 종료 후 턴 종료(`settleTurnEnd`) -> 상대 턴(turn 2, p2) 정상 시작. 어택 중 레스트 상태 변화 없음(이미 레스트였던 디지몬은 그대로, 액티브였다면 액티브 유지).
- `node scripts/soak.mjs 60`: 0 distinct errors, `node scripts/audit-effects.mjs`: 100.0%.

## 남은 가정
- 「오메가몬」/「X항체」는 카드 명칭(〈룰〉 명칭 취급 포함) 기준으로 해석. 특징 「X항체」까지 인정하려면 조건 한 줄 추가 필요.
