## 엔진/컴파일러 공통 수정 (다른 카드에도 영향)
1. **어셈블리/디지크로스 "-N: …" 줄**: 직전 효과 본문에 붙어 `manualCost` 확인 프롬프트를 만들던 문제 → `parseEffectSegments` 에서 제거. (기존 카드도 해당. 이 때문에 가려져 있던 BT26-085 의 "무비용 진화로 벗어나지 않는다" 대체 효과를 새로 구현.)
2. **어셈블리 재료 파서**: `《키워드》를 가진`, `색이 서로 다른`, "그린인 Lv.5×Lv.4×Lv.3"에서 첫 항목의 색이 모든 항목에 적용되도록 수정, 서로 다른 색 판정 추가.
3. **꼬리 문장 컴파일(`tailSentenceOps`)**: `[턴 1회]` 접두어, "등장시키거나 사용할 수 있다", "지불하는 코스트 -N 하여 진화시킬 수 있다".
4. **대체 효과(`surviveCost`/`parseSurviveAbility`)**: 겹쳐진 카드를 시큐리티 위로, 자신의 디지몬 1마리를 액티브/레스트, 명칭 조건 다른 디지몬(양측) 소멸, 무비용 진화, "레스트 상태인 …"·"《블로커》를 가진 …" 대상.
5. `preventRest` N마리(명)는 서로 다른 대상, `extreme.stat='sources'`(진화원 가장 적은), `evolveEffect` 성공 플래그(`ctx._evolvedByEffect`), `s8_playOrUse` 진화원의 디지몬/테이머 등장(`srcPlay`), `n5_jogressPair` 조건 함수, `resolveDigimonBattle` 진화원 매수 비교(`state._battleCompareSources`).
6. `scripts/qa/lib-s1.mjs`: 헤드리스 `drain` 이 효과로 시작된 어택을 `st._qaAtk` 에 기록.

## 감사 지표의 허점 (참고)
`audit-effects` 는 `【서로의 턴】` 계열 세그먼트를 (a) 워처 문법에 걸리는지, (b) 본문 전체가 컴파일되는지만 본다. 그래서 (1) 트리거가 실제로 발생하지 않는데도 본문이 컴파일되면 "커버"로 집계되고, (2) 조건문이 든 시큐리티 감소 워처는 `EW_UNSAFE` 로 조용히 수동 처리된다. EX13 에서는 이런 항목 전부를 시나리오로 확인해 훅/스크립트로 채웠다(`ewTrusted` 표시).
