# AND/OR 검증 로그 ("와/과" = AND, "/"·"또는" = OR, "A와 B 1장씩" = 조건마다 1장)

## 구현 (src/effects.js)
| 항목 | 내용 |
|---|---|
| `parsePickGroups` | "A와 B 1장씩 / 각각 / 옐로와 퍼플의 디지몬 카드 / N장과 N장" → `groups:[{filter,max,label}]`. 색 나열은 조건별로 전개, 각 조건 안의 `/`·`또는`은 OR |
| `criterionFilter` | 이해 못 하는 조건은 `{category?, desc}`로 완화(단일 카드 오픈 시 필터가 사라지던 버그 제거). 테이머/옵션 카드 OR, 「A」 또는 특징… OR |
| `pickByGroups` | 조건별 프롬프트(조건명 표시), 한 카드는 한 슬롯만, 이분매칭으로 다른 슬롯을 굶기는 선택 방지 |
| `moveEach` op | 패/트래시/진화원 → 덱 아래 / 이 디지몬 진화원 / 코스트 없이 등장 / 패. 비용으로 쓰면 전 조건 충족 필요(부분 지불 불가) |
| `distributeEach` | "상대의 디지몬과 테이머 1마리씩", "Lv.3과 Lv.5와 Lv.7의 … 1마리씩" → 문장 분배 |
| 토큰 | "「A」와 「B」 토큰 1마리씩" 마지막 하나만 등장하던 버그 수정 |
| 필터 키 추가 | costEq, costMin, colorCount(Min), colorsNot, hasInherited, hasXros, 「X」를 포함하는(명칭 생략형), 《K》를 가진 |
| 조건 | 「A」와 「B」(와 「C」)가 있다면 = 전부(자신/진화원), 「A」 또는 …자신의 테이머 또는 …디지몬 = OR, "…있거나, …일 때" OR 조건(예전엔 무조건 발동) |
| strictCardFilter | 「A」와 「B」를 한 카드의 OR로 취급하던 것 제거 |
| 기타 | "덱을 위에서부터 N장", "패에 넣는다", 조건 뒤 "그 중/나머지" 문장 묶음, 상대 테이머 레스트/소멸/되돌림 |

## 조건 검증 (condtest, 16건)
AND 이름 2/3개, OR 이름, 명칭 포함 OR, 진화원 AND/OR, 종류 교차 OR, 이름 OR 특징 — 전부 통과.

## 실제 브라우저 (localhost:5588)
가트몬(ST10-04) 등장 → 프롬프트 "옐로의 디지몬 카드 1장" → 플롯트몬, "퍼플의 디지몬 카드 1장" → 피코데블몬 선택 → 패 2장, 남은 아구몬 덱 아래. 정상.

## 회귀
soak 60판 오류 0, audit-effects 100%.

## 남은 위험
- 조건 문장 100+건은 패턴 단위로 표본 확인(색/특징/명칭 OR, 이름 AND); 진화원 조건 "…있었을 때"(트래시에서 진화)는 수동 확인 유지.
- BT5-019(진화원 「A」 또는 「B」 1장마다), BT7-108, BT8-065는 "마다/되돌림" 누락이 있으나 AND/OR 범위 밖이라 미수정.
