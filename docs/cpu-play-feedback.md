# CPU 대전 플레이 피드백 (직접 플레이 → 불편한 점 → 수정)

방법: 실제 UI(클릭/탭, 합성 DragEvent 드래그, 키보드)로 CPU와 여러 판을 두면서 불편한 점을 기록·수정했다. 데스크톱(800×600 포함)과 375×812 폰 크기 모두 확인. 판수는 쉬움/보통/어려움 전부, 선공/후공 모두, 덱 3종(CS, CS2, T)을 섞어 진행했고, `🔁 재대전` 버튼 자체도 이 과정에서 반복 사용했다. (사람 쪽 조작은 `scripts/uibot.js`가 실제 DOM 클릭/드래그로 수행 — 그래서 "잘 두는 사람"이 아니라 "빠르게 UI를 다 밟아 보는 사람" 기준의 발견이다.)

표기: 심각도 상/중/하. 상태 = 수정 / 보류.

## 발견 목록

| 3 | 상 | 게임이 끝나면 보드가 통째로 빈 화면, 사유·승패 문구 없이 `승자: p2`만 표시, 재대전 없음 | 종료 시에도 마지막 보드를 읽기 전용으로 유지(CPU 패 공개), `🎉 승리!/💀 패배…` + 사유(로그의 승패 줄, 예: `p1 시큐리티 0에서 피격`), `🔁 같은 덱으로 재대전`, `새 게임 (덱 선택으로)` | 캡처 확인, 재대전 버튼으로 연속 10판 이상 진행 |

## 확인했지만 이미 괜찮았던 것
- 멀리건 화면: 선공/후공, CPU 결정 중/완료 표시, 내 버튼 활성 조건 모두 명확.
- 메모리 게이지(양쪽 숫자·마이너스/플러스 방향 라벨), 덱/시큐리티/트래시 카운터는 항상 표시.
- 투항: 확인창 있음. CPU 차례엔 패스/다음 페이즈/드래그 잠금.
- 어택 흐름: 대상/대상변경/카운터/블록/결과 단계 표시, CPU가 결정하는 단계는 버튼 잠금 + `🤖 CPU가 결정 중…`.
- CPU 강도는 시작 화면에서만 바꿀 수 있어(게임 도중 변경 UI 없음) "도중 변경 → 다음 판부터 적용"이 자연히 만족. 속도/일시정지는 도중에 바뀜.

## 보류 / 구현하지 않은 아이디어
- 소프트락 원인 ②의 근본 수정(효과 러너가 끝나지 않는 경로 규명) — `src/cpusearch.js`가 라이브 상태에서 롤백(`restoreState`가 `uiChoice`/`pending`/uid 카운터를 되돌림)하는 부분과 `main.js`의 `autoRunMandatoryPending` 상호작용을 그쪽 작업자가 확인해야 함. 현재는 워치독 복구로 정체 없음.
- 폰 상단 툴바(되돌리기/저장/리플레이/…)도 한 줄로 접기 — 화면의 20%를 차지.
- CPU가 마지막에 행동한 카드를 보드에서 잠깐 강조(카드 uid를 note에 실어야 해서 cpu.js 판단부와 얽힘).
- 로그 패널의 `CPU만 / 내 행동만` 필터.
- CPU 연출 `건너뛰기(Space)` 버튼 — 지금은 속도 `빠르게`로 대체.
- 첫 대전 온보딩 말풍선(한 줄 안내 #8이 최소 대체).
- 패스 확인을 설정으로 끄는 옵션(현재는 4초 재클릭 방식이라 방해가 작음).
