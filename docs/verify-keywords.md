점검 관점: (a) 효과 종류(상시/유발/즉시/처리/처리조건, 강제·임의, 타이밍, 횟수, 비용, 대상 없음일 때) (b) 엔진+UI+CPU/cpusim 동작 (부여/상실, 누적, 상속 줄, 지속시간)

## 수정

1. **cpusim `startAttack`가 no-op** — 효과로 시작하는 어택(≪진격≫ ≪볼텍스≫ ≪급습≫ ≪에그제큐트≫ ≪오버클럭≫, "이 디지몬으로 어택할 수 있다")이 헤드리스 CPU 시뮬(`test-cpu`, 탐색 CPU `cpusearch`)에서 통째로 사라졌다.
   `src/cpusim.js`: `effAtkQ` 큐 + `runEffectAttack()` 추가. 이펙트 큐가 비고 어택 중이 아닐 때 실행하며(main.js `startAttack`과 동일), 대상이 없으면 어택 자체를 선언하지 않는다(`anyActive`/`digimonOnly` 옵션 반영). `attack()`이 `declareAttack` 옵션(raid/noRest/ignoreEntry)을 그대로 전달.
2. **CPU가 【메인】≪딜레이≫(배틀 에어리어에 놓은 옵션)를 절대 발동하지 않음** (해당 카드 42종) — `cpu.js`에 `delay` 액션 추가(놓은 다음 턴부터, `mainAbilityPayable` 통과 시, 메모리 효과면 우선), `main.js` `api.useDelay`, `cpusim.js exec 'delay'`, `cpusearch.js` 라벨. 놓은 턴에는 열거하지 않는다(16-17-3).

## 남은 한계 (미수정, 낮은 빈도)

- ≪S 어택≫: 마지막 예정 체크 이후(전투 후 트리거 등)에 +1을 얻으면 `ctl.done`이 이미 확정되어 추가 체크가 없다 (16-4-2 예시는 체크 "도중" 획득만 확실히 처리). 체크 사이 획득/상실은 정상. 어택 종료 흐름(Task A 영역)이라 손대지 않음.
- ≪흡수진화≫: CPU 진화 비용 산정이 흡수 할인을 모른다(사람 플레이/룰은 정상). 실카드에 ≪흡수진화≫가 중복된 경우는 없음(BT3-056은 본문+상속 줄 동일 문구).
- ≪재기동≫: 상대 액티브 페이즈 처리 루프가 배틀 에어리어만 봄(육성 에어리어에서 ≪트레이닝≫으로 레스트한 재기동 디지몬은 상대 턴에 안 일어남). 해당 조합 카드 없음.
- ≪충돌≫: 블록 가능 목록이 `main.js eligibleBlockers`와 `cpusim.js`에 각각 있음(둘 다 레스트 가능·액티브·noBlock·대상 제외로 일치 확인). UI 흐름이라 헤드리스 시나리오는 키워드 감지까지만.

## 상속(진화원) 줄 · 지속시간 · 상실 (공통)

- 진화원 줄에 적힌 키워드는 그 카드가 진화원일 때만 상단에 부여(방벽/재기동 시나리오), 진화원이 빠지면 사라짐, **뒷면 진화원은 아무것도 빌려주지 않음**.
- `grantKeyword`의 `turn`은 턴 종료 정리(`clearExpiredModifiers`)에서 만료; `nextOpponentTurn` 등은 상대 턴까지 유지. `loseKeyword`는 이후 부여가 이기고 지속시간 종료 시 복구(15-8-2-5).
- 조그레스/어플 합체/디지크로스/어셈블리/링크는 기존 테스트(`qa-slice5-r2-*`, `test-cs-evolution`)와 시나리오에서 대표 케이스만 재확인.
