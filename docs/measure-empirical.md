# 실측: 게임이 실제로 어떻게 흘러가는가 — CPU 대 CPU 대규모 실험 (총 267,650판)

측정 전용 작업이다. 엔진(`src/state.js`·`engine.js`·`effects.js`)과 CPU(`src/cpu.js`) 소스는 수정하지 않았다. 버그로 보이는 것은 §9 에 목록만 적었다.
모든 수치는 **이 시뮬레이터의 CPU(hard 휴리스틱)가 둔 게임**에서 나온 것이다. 사람에게 그대로 옮겨지는 결론과 아닌 결론을 §8 에서 구분했다.

## 0. 방법

### 0.1 하니스 (scripts/measure/)
| 파일 | 역할 |
|---|---|
| `lib.mjs` | 한 판 실행(`playGame`), 덱 생성기, 정책 래퍼, 통계(Wilson) |
| `exp.mjs` | 실험 정의 (`gen(i)` 는 (실험명, i)에 대해 결정적) |
| `worker.mjs` / `run.mjs` | worker_threads 11개로 병렬 실행, 판별 원자료를 `D:\measure-out\<exp>.json` 에 저장 |
| `analyze.mjs <exp>` | 표/신뢰구간/로지스틱 회귀 출력 |
| `repro.mjs` | 저장된 판을 인덱스로 재실행해 동일성 검증 (base 30/30 판 완전 동일) |
| `run-all.sh` | 전체 실험 순차 실행 |

재현: `PER=3000 sh scripts/measure/run-all.sh` 후 `node scripts/measure/analyze.mjs <exp> < /dev/null`
(`mem2`, `handicap` 은 run-all 에 없음 → `node scripts/measure/run.mjs mem2 - 11`). 원자료 총 약 370MB (C: 디스크가 가득 차 D: 로 옮김).

### 0.2 엔진을 쓰는 방식
- `createSim`(src/cpusim.js) 로 실제 규칙 함수(state/engine/effects) + `Cpu.planMain / planBreeding / decideBlock / decideCounter` 를 그대로 사용. 턴 루프는 `scripts/test-cpu.mjs` 와 같다 (턴 상한 90, 판당 시간 상한 40초; 실측 중 stall 0, 오류 0).
- **시드**: 엔진이 `Math.random` 으로 셔플·코인플립을 하므로 판마다 `Math.random` 을 mulberry32(hashSeed(실험명, i))로 교체 (Cpu 의 rng 도 이를 따름). 같은 (실험, i) → 같은 판 (`repro.mjs` 로 확인).
- **선후공 강제**: `E.beginGame(state, first)` 로 선공을 지정 (코인플립 대신). 실험은 (변형 좌석 p1/p2) × (선공 p1/p2) 2×2 균형 설계 → 좌석·선공 편향 제거.
- **멀리건**: `Cpu.shouldMulligan` 대신 정책 함수를 호출 → 가능한 값 `cpu / keep / always / noLv3 / cost3 / lv3or4`.
- **좌석별 TUNE 오버라이드**: `Cpu.TUNE` 는 모듈 전역이다. `cfgOf(p)`(cpusim 이 planBreeding/decideBlock/decideCounter 직전에 호출) 와 내가 감싼 planMain 이 매번 해당 좌석의 TUNE 값을 덮어쓰고(동기 실행이라 안전) → 한 판에서 두 좌석이 서로 다른 TUNE 을 쓴다.
- **덱**: (a) `genDeck` = test-cpu 의 coherentDeck 계열(단색/2색 합법 50장+디지타마 최대 5, Lv3/4/5/6·테이머·옵션 수를 조절) 40개 풀 (미러 대결 = 덱 요인 제거), (b) 무작위 조성 덱 (회귀용), (c) **의사 스타터**: `data/decks.json` 이 비어 있어(`{}`) 실제 스타터 목록이 없으므로 ST## 세트 카드로 고정 시드(424242)로 한 번 만든 임의 구성 16개 — **진짜 스타터가 아님**.
- **사용자 덱 DB(IndexedDB)** 는 헤드리스에서 접근 불가 → 미포함.
- 신뢰구간: 비율은 Wilson 95%, 차이는 Wald 95%, 회귀는 IRLS 로지스틱(z 는 Wald). "Δ" 는 50% 대비 변형측 승률 차(%p). 통제 `cpuSelf`(동일 정책끼리, 기대 50%) 6개 실험 합산 49.5% [48.7, 50.3] (n=16,150) → 측정 오차 규모 확인용.

## 2. 기본 통계 (base, hard-hard, 15,000판)

- **게임 길이**: 양측 합산 턴 평균 **10.1** (중앙 10, p10 8, p90 13; 최소 3, 최대 37). 즉 **각자 약 5턴**. 행동 수(판 전체) 평균 ≈ 30.3, 중앙 30. 승리가 나는 본인 n번째 턴: 4턴 22%, 5턴 36%, 6턴 28%, 7턴 8%, ≤3턴 2%, ≥8턴 3%.
- **종료 방식**: 시큐리티 0 에서 직접 피격 **14,997 / 15,000 (99.98%)**, 덱아웃 3판(0.02%), 항복 0, 영구순환 무승부 0. 다른 실험 전체(267,650판)에서도 덱아웃은 전체 대비 ≤0.1% 수준(passive99 같은 극단 arm 에서만 28판). → **이 규칙·이 CPU 에서 승부는 100% "시큐리티를 깨는 속도"** 이고 덱아웃 전략은 무의미.
- **선공 승률**: 전체 267,650판 합산(handicap 제외) **48.9% ±0.2** (n=246,650). 미러 50.0% [48.6, 51.4], 교차 49.8%, 의사스타터 46.9% [45.5, 48.3]. **선공이 불리하지도 유리하지도 않고, 오히려 후공이 약 1%p 유리**한 정도다 (선공은 1턴 드로우가 없고 메모리 0 에서 시작).
- CPU(hard)의 멀리건 비율 18.6%.

### 메모리/턴 종료 (base 136,351 턴, 마지막 턴 제외)
- 턴 종료: **패스 5.3% / 메모리 초과 자동 종료 94.7%**. 초과 종료 시 상대에게 넘긴 메모리 평균 2.57 (분포 1:16% 2:31% 3:37% 4:11% 5:4.5%, 6 이상 ≈0%). 넘긴 메모리 전체 평균 **2.59**. 즉 게임은 사실상 매 턴 "메모리를 다 쓰고 2~3 정도 넘기는" 식으로 진행된다.
- 패스할 때 남기고 버린 내 메모리 평균 0.66 (0 남김 60%, 3 이상 7%). **패스는 남은 내 메모리를 버리고 상대에게 정확히 3을 준다**(규칙 6-5-1-7-1) → 메모리를 남기고 패스하는 것은 두 배로 손해.
- 그 턴에 넘긴 양별 그 플레이어의 최종 승률 (교란 큼): 1–2: 48.4%, 3: 44.6% (=패스 위주), 4–5: 50.6%, 6–10: 55.9% (n=145).

## 3. 오프닝 결정

### 3.1 멀리건 (mull, arm 당 3,000, 미러 덱, 변형측 vs CPU 기본)
| arm | A 승률 [95% CI] | Δ |
|---|---|---|
| keep (항상 킵) | 49.6% [47.8, 51.4] | -0.4 |
| always (항상 멀리건) | 49.7% [47.9, 51.5] | -0.3 |
| noLv3 | 50.5% [48.7, 52.3] | +0.5 |
| cost3 | 49.6% [47.8, 51.4] | -0.4 |
| lv3or4 | 48.7% [46.9, 50.5] | -1.3 |
| cpuSelf | 48.6% [46.8, 50.4] | -1.4 |

정책 간 차이는 통계적으로 구분되지 않는다. 그러나 **멀리건 반사실 비교**(forced-keep arm 의 나쁜 핸드 vs 해당 규칙 arm 에서 실제로 멀리건한 판)는 뚜렷하다:

| 규칙 | 조건 해당률 | 그대로 킵 | 멀리건 | 멀리건 이득 |
|---|---|---|---|---|
| Lv3 없음 | 15.7% | 39.7% [35.4, 44.2] (n=471) | 47.2% [42.9, 51.6] (n=508) | **+7.5%p** [1.3, 13.7] |
| 코스트≤3 Lv3 없음 | 18.3% | 41.6% (n=548) | 49.8% (n=534) | +8.2%p [2.3, 14.1] |
| 코스트≤4 Lv3/Lv4 없음 | 6.7% | 35.8% (n=201) | 48.9% (n=182) | +13.1%p [3.2, 22.9] |

- 강제 킵 시 핸드별 승률: Lv3 0장 39.7% / 1장 50.6% / 2장 51.9% / 3장+ 52.5%. 옵션 2장 이상 42.9%, 테이머 있음 47.2%.
- 해석: 이 규칙에서 **멀리건은 페널티가 없다**(새 5장 뽑기). 그래서 "항상 멀리건"이 "항상 킵"과 같은 것(랜덤 5장 = 랜덤 5장). 손해는 **Lv3 가 없는 핸드를 킵하는 것 하나뿐**(-10%p). Lv3 이 이미 1장 이상 있으면 킵/멀리건 차이는 ~1~2%p 이하로 사실상 무의미. CPU 규칙(hard: 코스트≤3 Lv3 없고 Lv3 2장 미만이면 멀리건, 예외 조건 있음)은 이미 이 효과를 대부분 잡는다.
- **오프닝 핸드의 값**: 멀리건 후 핸드에서 Lv3/Lv4/Lv5+ 한 장 더 ≈ 회귀 +1~2%p, 테이머·옵션 한 장 ≈ -4%p (§5).

### CPU 인공물 (사람 플레이에 그대로 옮기면 안 되는 것)
- 테이머·옵션이 손해로 나오는 것: CPU 는 옵션을 "핸드에서 점수 임계 초과 시 사용" 정도로만 쓰고 테이머를 3.6점 정도의 등장 행동으로만 취급하며, 카드 개별 효과(드로우/메모리 회수 등)를 계획에 반영하지 못함.
- 블로커·리커버리 카드 계수: 방어 판단이 단순(블록 0.17회/게임) → 블로커가 있는 덱도 값이 안 나옴.
- 게임 길이(각자 5턴): CPU 는 5턴 안에 시큐리티 5장을 깨는 식으로 진행 → 이런 극단적 속공 환경에서 시큐리티 가치가 과대 측정됐을 수 있음(사람은 방어 전략으로 늘어날 수 있음).
- 임의 덱(색 일관 무작위 카드)이므로 시너지가 없는 덱들의 평균: 진화 라인이 맞는 실제 덱과는 다름.
- 의사 스타터: 진짜 리스트가 아님.
- hard 를 기준으로 한 국소 변형: TUNE 값 하나씩 바꾼 결과이므로 조합 최적점은 아님.

## 10. 개선 제안
### CPU AI
1. **메모리 넘김 페널티 축소** (`hardLimit` 5→10, `hardGw` 1.0→0): 즉시 +4~5%p (mem/mem2). 특히 `dangerous`(시큐리티≤2 & 상대 디지몬≥2) 분기의 한도 3 고정도 재검토(`dangerFree` +5.4%p).
2. 멀리건 규칙 유지 (이미 Lv3 없음 핸드 킵의 손해를 회피). 다만 `easy` 는 15% 무작위 멀리건 등 노이즈가 커서 약함(4%p 미만 승률) — 사람 초보 대상으로는 적당.
3. 공격 점수는 국소 최적에 가까움 (aggro/reserve/gain2/chump 튜닝 차이 없음) → 다음 이득은 카드별 효과(옵션·테이머·블로커) 활용 개선에서 나올 가능성이 큼 (옵션/테이머 가치 평가 모델 필요).
4. 육성 정책은 "즉시 이동 + 즉시 재부화"가 최적 근처; 변경 불필요.
5. `hard` 와 `normal` 격차(7.5%p)가 작음 → hard 를 더 차별화하려면 위 1번과 옵션·테이머 사용 개선 적용.

### 시뮬레이터 UX
1. **메모리 초과/소멸 경고**: 패스 클릭 시 "남은 메모리 N 이 사라지고 상대는 3 을 얻습니다", 코스트 지불 시 "상대에게 K 를 넘깁니다" 표시 (넘김 ≤3 은 '패스와 동일' 표시).
2. **멀리건 조언**: "Lv3 디지몬이 없는 핸드는 멀리건 권장 (킵 시 승률 -10%p, 멀리건은 페널티 없음)" — 초보 모드에서 핸드 평가 배지.
3. 부화 조언: 1턴 육성 페이즈에서 부화하지 않고 넘어가려 할 때 확인 팝업 ("1턴 부화 누락 -8%p 상당").
4. 시큐리티 가치 표시: 남은 시큐리티 수와 "상대가 이번 턴 최대 어택 수"를 항상 표시.
5. 육성 에어리어에서 Lv3 이 되었을 때 "이동하면 새 알을 부화할 수 있음" 힌트.
6. 게임 종료 화면에 요약 지표(시큐리티 잔량 그래프, 턴별 메모리 넘김, 첫 Lv4 턴) 표시 — 학습용 (본 실험에서 쓴 턴별 기록 형식 재사용 가능).
