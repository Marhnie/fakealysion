# Open engine items, batch D (2026-09)

Regression scripts: `scripts/qa/qa-open-d-{once,playopts,cpudelay,lm019,misc}.mjs` (each prints `pass N, fail 0`).

## Fixed

1. **Once-per-turn consumed by an effect that never asked anything (rule 15-7-1 / 15-14-1).** `Effects.onceGuard` (effects.js) now also gives the 〔턴에 N회〕 use back when the effect asked NO question and left the game state completely untouched (no legal target, unmet condition, nothing to play): a strict fingerprint that also includes private `_` flags on stacks (state-root caches ignored) plus "no new pending note". Cancelled-pick behaviour is unchanged. Wired everywhere the guard already was (main.js, cpusim.js, lib-s1). Test: `qa-open-d-once` (BT24-050 inherited 어택 시 with an empty hand, EX12-050 【메인】 with nothing playable, positive control).
2. **Bespoke effect-driven plays did not offer play-cost options.** New shared `FX_HELPERS.effectPlayPlan(ctx, who, zone, idx, cost)` (effects.js): tamer/trait/s1 hand-play discounts, hook play-cost options (EX6-006 …, `S.effectPlayHookDiscount`), DigiXros and Assembly, exactly as `s8_playOrUse`. Used by shard3 `playPay` / `playFreeWhere` (about 10 cards), shard17 reveal-and-play (paid and free), shard6 `playFreeChoose`, shard12 `playFreeHandTrash`. Test: `qa-open-d-playopts` (BT15-096 with EX6-006 hook option).
3. **CPU and 《딜레이》 event bullets.** `cpusim.js` (headless driver, also used by test-cpu / lookahead) now mirrors main.js's delay branch: checks the option is in the battle area and not placed this turn, evaluates the bullet gate, asks the CPU (confirmEffect), discards through `S.discardForDelay` and runs the bullet. `cpu.js` confirmEffect declines when the gate fails (would only waste the card). The browser CPU already went through main.js `runPendingScript` (its `ctxChoose` is answered by the CPU) and the main-phase 《딜레이》 action existed before. Test: `qa-open-d-cpudelay` (BT17-096 success, same-turn refusal, BT24-098 failing gate declined).
4. **Misc engine items**
   * LM-019 holder ordering: `flushRuleChecks` and `ruleSweepDP` (DP 0 rule-check sweeps) now order simultaneous deletions through `orderSimulDelete`; new `S.deleteSimul(state, p | entries, uids, cause)` replaces the per-stack delete loops of the bespoke wipes (shard4 s4_destroyAllOwn / chosen-sum destroy, shard10, shard13, shard14 x2, shard35 x2, shard73 x2, effects.js sum destroy). Test: `qa-open-d-lm019`.
   * EX2-007 in id-based helpers: shard7 / shard14 checks that are really about battle-area stacks (`isDig(info.stack.cardId)`, `isDig(s.cardId)` …, 31 sites) now use `S.isDigimonLike(stack)`. ## Still open / caveats

* Effect plays in the ~90 remaining bespoke `S.playFreeFromZone` call sites (mostly "play this card from the trash", single-card scripts in shard1/4/5/11/13/19/31/48/51 …) do not call `effectPlayPlan`; they are free plays of a fixed card where a DigiXros/Assembly declaration is very unlikely. Only the shared pickers listed above were converted.
* The "no question + no state change" refund is a heuristic: an effect whose only outcome is stored in a key the fingerprint skips (`log`, `art`, `contTs`, `turnEffectUses`, `hookEvt`, `attackCtx`, root-level `_` caches) would be judged "not activated". No existing scenario hits this.
* `inferLeftTo` is a heuristic over the final zone contents (last 4 hand cards, deck ends, security ends); a bespoke bounce followed by more than 3 additional hand additions in the same script is missed (status quo behaviour).
* The 《딜레이》 CPU logic in the browser was not re-run in a real browser (main.js is browser-only); the headless driver is covered by `qa-open-d-cpudelay`.
* LM-019 ordering covers effect wipes routed through `orderSimulDelete`/`deleteSimul` and rule-check sweeps; battle damage that deletes two stacks at once (attacker + defender) is not reordered.
