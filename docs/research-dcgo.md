## 3. 관찰 요약

칭찬(근거: 기사/비교글): 완전 무료, 자동 메모리/효과 처리, 고해상도 아트, 커스터마이징, 커뮤니티 개발자 활발. Drasil은 무설치 접근성.

불만/약점(근거: 패치노트 이슈, 댓글, 비교글):
- 설치 장벽: 런처/관리자 권한/VC++ 재배포/카드 이미지 자산 다운로드. (FAQ 항목 대부분이 설치 트러블)
- 자동 효과의 엣지 케이스: 동시 발동 중 하나만 처리됨, 트래시 재진입 효과, 복사 효과, 면역 상호작용, 블리츠 이중 등장, 디지크로스 배치 실패, 디싱크(특정 카드), 소프트락(특정 카드끼리 대치).
- 성능: 큰 필드 저하. 소멸 시 트래시 선택 화면에서 대기 효과가 표시되지 않는 UI 이슈 등 "무엇이 발동 대기인지 표시" 문제.
- 세트 반영 지연(TTS 모드), 덱 임포트 혼란.

룰 모호성 처리: DCGO 내부의 순서 선택/선택적 효과 UI는 **확인하지 못함**. 룰 측면 근거로는, 자기 효과 순서 선택 -> 턴 플레이어 우선이 원칙이고, 효과 처리 중 새로 유발된 효과는 대기 중인 효과보다 먼저 발동(룰링 요약). 우리 엔진은 `pickPendingOrder`로 순서 선택이 이미 있음.

## 5. 우리 시뮬레이터가 이미 앞선 점 (참고)
무설치 브라우저+모바일 터치, 진화/조그레스 조합 UI, CPU 4수 읽기, 되돌리기/리플레이, 덱 통계/샘플핸드/체크업, 필드 위 효과 출처 표기와 VFX, 퍼저 기반 자동 검증.

## 6. 따라 하지 말 것
- **데스크톱 설치형 + 카드 이미지 별도 추출/설치**: FAQ의 절반이 설치 트러블. 우리의 무설치 이점을 버리는 것.
- **보드 16장 같은 하드 제한**: 성능 한계를 규칙에 노출하는 방식. 우리는 DOM 최적화로 풀어야 함.
- **"완전 자동" 을 무조건 앞세우기**: 자동화 버그가 곧 게임 파괴(소프트락/디싱크)로 이어짐. 현행 "자동 + 수동 도구 패널 폴백" 유지가 더 안전.
- **래더/랭킹**: 서버, 부정행위, 금지목록 이중 운영 비용이 큼. 방 코드 대전이 먼저.
- **Discord 시트 기반 버그 관리**: 규모 작은 우리에겐 repo 내 표 + 신고 JSON이 충분.

## 7. 키워드 효과 점검 관련 메모 (사용자 요청 컨텍스트)
사용자 지시: 연계(링크)와 레스트 시 효과는 【어택 시】와 같은 타이밍. 이 조사에서는 그 부분의 외부 근거는 찾지 못했고(룰북 확인 필요), 시뮬레이터 코드 점검은 이번 조사 범위 밖이라 **수행하지 않음**. 별도 작업으로 attack-timing 계열(연계, 레스트 시, 어택 시, 블록 시, 시큐리티 체크 전/후) 트리거 일치 점검을 권장.
