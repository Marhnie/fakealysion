# CPU가 옵션·테이머를 쓰는 방식 — 개선 확인 리포트

배경: `docs/cpu-human-decks.md`(사람 덱 학습 기반 CPU 덱 진화)에서 CPU가 진화시킨 덱은 사람 덱(테이머 7.1장/옵션 7.5장)과 달리 테이머·옵션이 거의 없었다(이전 CPU 덱 2.0/2.8, human-seeded 출하 덱 1.0~1.4/0.2~0.5). 원인으로 지목된 것이 "CPU가 옵션·테이머를 잘 못 쓴다"는 것이었다. 이 작업은 그 개선을 마무리하고 실측으로 검증한다.

이 문서를 쓰기 시작한 시점에 `src/cpu.js`/`src/cpusearch.js`에는 이미 옵션/테이머 정책 개선이 커밋돼 있었다(`git log --oneline -- src/cpu.js`의 최신 커밋). 즉 이번 작업은 "0부터 구현"이 아니라 **이미 들어간 수정을 검증하고, 부족하면 마저 고치는 것**이었다.

## 1. 이미 들어가 있던 수정 (검토 결과)

`git diff` (이 작업 시작 시점 기준 커밋 2개 전 `6f475cf` → 최신)로 확인한 변경 내역, `params.optTam`(기본값 1, hard/expert에만 적용; 0 = 수정 전 동작)으로 온/오프 가능:

1. **"상대" vs "상대의" 정규식 버그**: 옵션/테이머/카운터 텍스트 분류가 전부 `/상대의\s*(디지몬|테이머)/`만 검사해서 "Lv.6 이상의 **상대 디지몬** 1마리를 소멸시킨다"(의 없음, 예 BT4-112)처럼 흔한 표현의 제거/바운스 옵션을 전부 `misc`(점수 2)로 오분류하고 있었다. `상대(?:의)?\s*(디지몬|테이머)`로 수정.
2. **대상 합법성 검사 추가** (`optionTargets`): 소멸/바운스/레스트 옵션이 "등장 코스트 N 이하", "Lv.N 이상/이하", "DP N 이하", "액티브/레스트 상대"를 실제로 만족하는 상대 디지몬이 있을 때만 가치를 매기도록 함(대상이 없으면 카드+메모리 낭비를 막음).
3. **무료 진화 옵션 인식** (`evoPairPossible`): "진화 코스트를 지불하지 않고 진화시킬 수 있다"류, "Lv.5→Lv.6 진화 코스트 -4"류를 손에 실제로 짝지을 진화 대상이 있을 때만 `free`/`free`급 점수로 인식(이전엔 `misc`).
4. **방어형 옵션 인식** (hard/expert 전용, `FIX>=2`): "상대 디지몬은 어택/블록할 수 없다"류를 자신이 수세에 몰렸을 때(시큐리티 적음 + 상대 디지몬 다수)만 가치 있게 평가.
5. **테이머 선후 순서** (`tamerBonus`): 등장/진화 코스트를 깎는 테이머(`(진화|등장) 코스트… -숫자`)는 먼저 내는 게 이득이므로 `tamDisc` 가산(기본 1). 메모리 엔진 테이머의 즉시 가산(`engBonus`)은 실측 결과 선손해라 기본 0으로 둠(주석에 명시).
6. **《블래스트 진화》 카운터 전면 개편**: 이 카드풀의 유일한 【카운터】 옵션인데, 예전 임계값(danger>=2 & score>=1.5)이 "시큐리티 4장에 대한 공격"처럼 흔한 상황에서 패스하게 했다. 무료 진화(+DP, 공격자 소멸/레스트/되돌리기 등 부가효과)이므로 치명타이거나, 상대 턴 종료까지 내 시큐리티가 위험하거나 공격 DP가 높으면 항상 사용.
7. **소멸 카운터 분류**도 6과 같은 "상대"/"상대의" 버그를 hard/normal에서 수정.
8. **기프트 상한 분리** (`optGiftMax`/`tamGiftMax`): 메모리를 상대에게 넘기면서까지 사는 행동의 한도를 옵션/테이머 카테고리별로 따로 설정 가능하게 함(기본 10 = 사실상 무제한, 기존 `hardLimit`이 그대로 적용됨).
9. **탐색 빔 보장** (`cpusearch.js genActions`): 옵션/테이머/【메인】 능력/딜레이 후보는 휴리스틱 점수가 낮아 빔에 못 들어오는 경우가 많았는데, 각 클래스 중 최고 점수 후보 하나씩은 항상 빔에 포함(최대 +4개).
10. **15-7-1 선택 비용 응답** (`optionalCostAnswer`, 기존): 시큐리티 2장 이하로는 안 남기기, 손 마지막 카드는 안 버리기, 손 4장 이상이면 버리기 등 6개 케이스가 `scripts/test-cpu-options.mjs`로 회귀 테스트돼 있었다.

이 항목들은 `scripts/test-cpu-options.mjs`(26개 단정, 결정론적 보드 상황)로 이미 검증돼 있었고 재실행 결과 **26/26 통과**를 재확인했다.

## 5. 덱 진화 재실행 — 개선된 CPU로 더 나은 덱이 나오는가

`docs/cpu-human-decks.md`가 출하한 `data/cpu-decks.json`(사람 덱 학습 기반, 28덱)은 **옵션/테이머를 잘 못 쓰던 구버전 CPU**로 적합도를 평가해서 만들어졌다(사람 덱 테이머 7.1/옵션 7.5 대비 출하 덱은 테이머 1.39/옵션 0.54 — 재계산 수치, 문서의 1.0/0.2는 초기 집계). §1~2에서 CPU의 옵션/테이머 사용이 실제로 개선됐으므로, **같은 파이프라인을 지금의 `src/cpu.js`로 다시 돌리면 더 나은(더 테이머/옵션이 많은) 덱이 나오는지** 확인했다.

방법: `scripts/evolve-decks.mjs --mode evolve`를 `docs/cpu-human-decks.md`와 같은 설정(사람 덱 코퍼스 + 통계 prior, 인구 32, reps 2, 세대 앞 30% normal 이후 hard)으로, 예산 30분, 워커 8, 새 시드로 재실행 → 110세대(30.2분) → `--mode finalize`로 전체 건틀릿 재평가 → 76덱 출하(51색조합). 이어서 `--mode h2h`(N=400/쌍, Wilson 95% CI, hard, 양쪽 선후공)로 새 진화 덱을 사람 홀드아웃 40덱·기존 출하 덱(`old-cpu-decks`)·스타터·베이스라인과 맞대결시켰다.

| | 테이머(장/덱) | 옵션(장/덱) |
|---|---|---|
| 사람 덱(2,608덱 평균, 참고) | 7.1 | 7.5 |
| 기존 출하 덱(`data/cpu-decks.json`, 28덱, 구버전 CPU로 평가) | 1.39 | 0.54 |
| **새 진화 덱**(76덱, 지금의 CPU로 평가) | **3.22** | **1.92** |

기대대로 테이머는 2.3배, 옵션은 3.6배 늘었다 — CPU가 옵션/테이머를 더 잘 쓰니 진화가 그 카드들을 덜 페널티 주고 채택한다는 뜻.

**그런데 실제 대결 성적은 거꾸로다** (N=400, Wilson 95% CI):

| A | B | A 승률 [CI] |
|---|---|---|
| 새 진화 덱 | 기존 출하 덱(`old-cpu-decks`) | **40.3% [35.6-45.1]** |
| 새 진화 덱 | 사람 홀드아웃 40덱 | 60.5% [55.6-65.2] |
| 기존 출하 덱 | 사람 홀드아웃 40덱 | (100−32.8=) **67.2%** [62.5-71.7] |
| 새 진화 덱 | 스타터 21종 | 84.8% [80.9-87.9] |
| 새 진화 덱 | 베이스라인 12종 | 91.8% [88.6-94.1] |

새 진화 덱은 기존 출하 덱에게 **신뢰구간이 50%를 완전히 벗어나 유의하게 진다**(45.1% < 50%), 사람 홀드아웃 상대로도 기존 출하 덱(67.2%)보다 약하다(60.5%). 테이머/옵션이 훨씬 많은데도 전투력은 더 낮다.

**해석**: §2.1에서 이미 확인했듯, 이번에 고친 CPU로도 "테이머4+옵션6+필러4" 구성(`full`)이 "필러14"(`none`) 구성보다 유의하게 약하다(−6.3pp). 즉 **CPU가 옵션/테이머를 더 잘 쓰게 됐다고 해서, 옵션/테이머를 많이 넣는 덱 구성 자체가 강해지는 것은 아니다** — 이 카드 풀에서는 순수 디지몬(보드 전개·공격력)이 옵션/테이머보다 원체 효율이 높고, 적합도 함수가 그걸 그대로 반영해 진화가 다시 그쪽(더 많은 테이머/옵션)으로 갔음에도 결과적으로 더 약한 덱이 나왔다. 색 조합도 새 진화 덱은 상위권이 거의 전부 "레드/옐로/…/퍼플" 계열로 수렴해 다양성이 낮다(51개 색조합 중 출력됐지만 승률 상위는 12개 남짓에 집중) — 이 편중도 성능 저하의 한 원인일 수 있다.

**결론: `data/cpu-decks.json`은 갱신하지 않는다.** 새 진화 덱(`scratch/tmp/evolve2/cpu-decks-new.json`, 커밋 안 함)이 기존 출하 덱보다 유의하게 강하다는 증거가 없고 오히려 반대이므로, 교체할 근거가 없다. CPU 옵션/테이머 정책 개선은 §1~4처럼 실제로 유효하지만, "그러니 덱 진화도 다시 돌려 더 나은 덱을 뽑자"는 가설은 이번 재실행에서 **기각**됐다.
