## 방법 및 실제 수행 범위 (정직한 고백)

788개 항목을 전부 동일한 깊이로 검토하는 것은 이번 세션 예산 안에서 불가능했다. 실제로는 아래 순서로 진행했다.

1. 카드별로 그룹화해 788개 항목 전체를 훑어보며(skim), "구현이 틀리기 쉬운" 비자명한 룰(트리거 타이밍, 대체 효과 ≪디코이≫/≪수호≫, 동시 발동 순서, 색 조건 4-22, DP 소멸 효과 상한, 진화원 카드명 vs 특징 구분, 사용 코스트 자체 변경 vs 지불 코스트만 변경, 덱 오픈 후 파기 vs 직접 파기 등)을 우선순위로 표시했다.
2. 여러 카드에 걸쳐 **반복적으로 등장하는 공통 패턴**(제네릭 컴파일러/엔진 레벨 문제가 여러 카드에 동시에 영향을 주는 것들)을 추려서 실제 코드(src/effects.js, src/state.js)를 직접 읽거나, `node -e`/scratch 스크립트로 `Fx.compileToScript` 결과를 확인하거나, scripts/qa/lib-s1.mjs 기반 임시 시나리오를 만들어 실제 동작을 검증했다.
3. 자체 스크립트(shard*.js)가 있는 카드들을 우선 대상으로 삼아 텍스트별 구현을 코드 리딩으로 대조했다 (BT9-018, BT9-013/014, BT10-016/024/042/084/112, BT11-043/074/107, BT12-057/072/092 등).
4. 788개 항목 중 실제로 "카드 텍스트 확인 → 컴파일 결과/구현 코드 대조 → (필요시) 시나리오 실행"까지 마친 것은 대표 패턴 사례 + 표본 카드를 합쳐 대략 45~55개 항목/카드 수준이고, 나머지 대다수는 groupby 후 "당연히 맞는 카테고리(단순 예/아니오 확인성 질문, 이미 알려진 제네릭 규칙의 반복)"로 분류해 skim만 했다.

## 실제로 발견하고 수정한 버그

### "이 효과로 소멸하지 않았을 때" 판정이 ≪디코이≫/≪수호≫ 대체 효과에 속음 (제네릭 엔진 버그)

- **원인**: "DP N 이하의 상대 디지몬 1마리를 소멸시킨다. 이 효과로 소멸하지 않았을 때, ~" 류 텍스트에서 "소멸하지 않았을 때" 판정이 두 경로로 컴파일된다.
  1. `destroy` 오퍼레이션 내부의 `ctx._lastDestroyed` (문구가 정확히 "이 효과로 소멸하지 않았다면"일 때만 사용).
  2. **더 일반적인 경로**인 `runOne`의 `resDiff`/`resSnap` 기반 `ctx._res.deleted` (문구가 "이 효과로 상대의 디지몬이 소멸하지 않았을 때"처럼 조금이라도 다르면 이쪽으로 컴파일됨 — 이번에 실제로 문제가 된 EX2-012 등 대부분의 카드가 이 경로).
  둘 다 원래는 **"대상 플레이어의 배틀 에어리어 카드 수가 줄었는가"**(길이 diff)만으로 소멸 여부를 판정했다. 그런데 ≪디코이≫/≪수호≫는 "지정된 대상은 살리고 대신 다른 자신의 디지몬을 소멸시키는" 대체 효과이므로, 배틀 에어리어 길이는 어차피 줄어들어 "무언가 소멸했다"고 오판하고, 정작 지정한 대상은 살아있음에도 "이 효과로 소멸하지 않았을 때" 후속 효과가 스킵되는 버그였다.
- **공식 룰링과 대조**: EX2-012 메기드라몬 (id 3302) — "상대가 데코이를 발휘해 대상 디지몬이 소멸하지 않았다. 데코이를 발휘한 디지몬이 소멸했더라도 '이 효과로 소멸하지 않았을 때' 조건은 만족하여 후속 효과(서로 덱 5장 파기)가 발동한다." BT9-017 듀크몬X항체 (id 1814)도 동일 구조("최저 DP 디지몬을 소멸시킨다. 소멸하지 않았을 때 액티브가 된다" — 상대가 일부러 '효과로 소멸하지 않는' 디지몬을 대상으로 선택해 자신을 액티브로 만들 수 있음).
- **영향 카드(본 그룹 확인분)**: EX2-012 메기드라몬, BT9-017 듀크몬X항체. 다만 이 수정은 op 레벨(`case 'destroy'`)과 `runOne`의 `ctx._res` 계산 레벨에서 이뤄진 제네릭 수정이라, "…소멸시킨다. 이 효과로 소멸하지 않았을 때/했다면 ~" 패턴을 쓰는 다른 그룹 담당 카드들(예: EX9 계열 등)에도 함께 적용된다.
- **수정 내용**:
  - `src/effects.js`의 `case 'destroy'`: 각 분기(`last`/`thisStack`/`all`/`lowestDP`/기본 선택)에서 `S.deleteStack`의 반환값(성공 시 파기된 카드 배열, 대체 효과로 막히면 `null`)을 직접 추적해 `ctx._lastDestroyed`를 계산하도록 변경 (기존의 배틀 에어리어 길이 diff 방식 폐기).
  - `runOne`(같은 파일)에서, 방금 실행한 instr이 `'destroy'`였다면 `resDiff`가 계산한 일반적인 `ctx._res.deleted`(길이 diff 기반, 대체 효과에 취약)를 `ctx._lastDestroyed` 기반의 정확한 값으로 덮어쓰도록 추가.
- **회귀 검증**: 새 파일 `scripts/qa/qa-audit-g2-destroy-decoy.mjs` 작성.
  1. ≪디코이《블랙》≫ 보유자(BT6-059)가 있을 때 EX2-012류 효과로 대상을 지정하면 대상은 생존, 디코이 보유자가 대신 소멸하지만 "소멸하지 않았을 때" 후속 효과(서로 덱 5장 파기)는 정상 발동함을 확인.

## 시간 부족으로 skim만 하고 넘어간 것 (명시적 스킵)

788개 항목 중 대다수(약 700개 이상)는 다음과 같은 반복 패턴으로 분류해 개별 검증 없이 skim만 했다:

- "오픈한 N장 카드 중 조건 A인 카드와 조건 B인 카드가 둘 다 없어도, 하나만 있으면 그것만 가져온다" 류의 반복 질문 (BT8-009/021/033, BT9-008/020, BT10-008/046/058/073, EX3-007/037/048, BT11-007/020/023/062 등 수십 장에서 동일 패턴 반복) — 제네릭 "가능한 한 처리한다" 규칙이 엔진 전반에 일관되게 구현되어 있다고 가정하고 개별 검증 생략.
