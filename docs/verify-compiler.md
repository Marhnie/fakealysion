# 범용 텍스트 컴파일러(compileToScript) 검증 로그

방법: `S.parseEffectSegments`로 카드별 세그먼트 전체를 덤프(카드별 스크립트(shard1~8)가 있는 것은 제외, 자신/상대/서로의 턴 세그먼트는 `parseWatcherTrigger().effect`만 사용) → op/패턴별로 군집화 → 원문 대비 스크립트 의미 확인 → 컴파일러 수정 → 실제 보드 상태에서 `ctx.choose`를 스크립트로 흉내내 결과 검증.
도구(스크래치패드 `cv/`): `dump.mjs`(전체 덤프), `samp.mjs`(op별 샘플), `show.mjs`(카드별), `cost.mjs`·`man.mjs`·`mada.mjs`·`that.mjs`(군집), `diff.mjs`(수정 전후 비교), `xcheck.mjs`(자동 교차검사: 드로우 수/메모리 합/DP 대상 측/지속시간/소멸 수/조건 누락), `boot.mjs`+`t1~t4.mjs`(보드 실행 검증 51건), `exec_all.mjs`(전 세그먼트 4,915개를 채워진 보드에서 실행: 예외 0).
규모: 카드별 스크립트가 없는 세그먼트 5,216개 중 스크립트 생성 4,918개. 수정 후 `audit-effects` 100%, `soak 40` 오류 0(4회 반복).

## 미해결 / 알려진 한계
- 진화원 아래에 놓기(어셈블리/디지크로스형)·덱 아래로 되돌리기 비용은 `manualCost`. "이 효과로 …사용/진화/조그레스 결과", "그 카드가 …", "배틀 이외로 소멸하고 있었다면" 조건은 수동 확인(약 50건).
- "마다" 중 문장 중간형("…하고, 자신의 트래시 N장마다 …"), "이 효과의 상한 +N"류(약 60문장)는 dropped 문장으로 남아 수동 안내됨.
- 부여 효과 중 【서로의 턴】/【상대의 턴】 감시형(레스트했을 때, 블록당했을 때)은 `noop` 안내(엔진에 이벤트 훅 없음).
- "이 효과로 소멸하지 않았다면" 이 여러 op 뒤에서 참조하는 경우, 마지막 op 결과만 추적(`ctx._res`).
- shard9 대체 스크립트는 필요한 카드가 없어 만들지 않음(원문 모호로 못 고치는 카드 없음).
