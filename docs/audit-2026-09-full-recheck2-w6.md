# Q&A 전수 재점검 (2차) — Worker 6 (2026-09-26)

Scope: `data/rulings/all.json` array indices **3335–4001** (667 entries, Q&A ids **3992–4705**, incl. the gap ids inside that block).
Cards: LM-01/03 (LM-003~038), RB1, P-0xx/P-1xx promos, BT20 (155 entries), BT21 (111), ST20/ST21, plus the multi-card generic rulings that list dozens of cards each (「記述がある」, ≪효과를 받지 않는다≫, 「ことで」, BT4-011 x28 …).
All numbers below in `idx` form ("idx 3339") are array indices; the matching Q&A id is given in brackets when a fix is tied to one.

## Method

1. All 667 entries were deduplicated on (question, answer): **441 distinct rulings** (the rest are the same FAQ reprinted per card / per set).
2. Every distinct ruling was read. Card texts (`cards_full.json`, after `loadData` normalisation) and the implementing code (`src/cards/*.js` scripts, `effects.js` compiler output via `compileToScript`, `state.js`, `engine.js`, `main.js` where the ruling is about the turn/attack flow) were compared. Compiled scripts of the ~310 cards touched by the block were dumped and read segment by segment (`scratch/w6/dump2.txt`).
3. Where practical the ruling was reproduced headlessly on the real engine (`scripts/qa/lib-s6.mjs` harness). New regression suites: `scripts/qa/qa-w6-a.mjs` (LM/RB1), `qa-w6-b.mjs` (P promos), `qa-w6-c.mjs` (ST20/21, BT20/21, misc). Every fix below has a scenario that fails before / passes after.
4. Findings: rulings that were already implemented correctly (the vast majority — earlier waves fixed most of the generic ones: ことで all-or-nothing, 효과를 받지 않는다 semantics, 등장 불가 locks, forced attacks, 「その後」 running without its condition, security-check order, DP-0 batching, once-per-turn bookkeeping, tokens, etc.) were simply confirmed; only real deviations were fixed.

## Totals

- Entries reviewed: **667 / 667** (441 distinct rulings).

- Real bugs found and fixed: **15** (list below), touching 24 cards/families.
- Left unresolved with reasons: 6 (see the end).

## Not fixed / unresolved

1. **LM-019 보코몬 (idx 3345/3611, ids 4002/4268)** — the printed 「…벗어날 때, 이 디지몬을 소멸시키는 것으로, 벗어나지 않는다」 is implemented (generic printed-survive parser), but the ruling says one activation protects *all* digimon that were leaving at that moment. The engine resolves each deletion of a simultaneous group on its own, so with 2+ 감마몬 in one wipe only the first is saved. Needs a group-aware replacement pass in `deleteStack`/`orderSimulDelete`; too invasive for a surgical edit.
2. **BT8-095 / ≪아머 퍼지≫ (idx 3999, id 4705)** — after the attacker loses a security battle but *survives* via a replacement (아머 퍼지, 디코이 …) the remaining ≪S 어택≫ checks should continue. `battleSecurityCheck` marks the check `done` on defenderWins/tie and the callers (main.js/cpusim/harness) delete the attacker afterwards. In the browser the replacement is a parked interactive choice, so continuing the loop needs a hook into `resumeReplacement`. Not changed.
3. **Forced 【등장 시】 (BT20-037 family, idx 3686/3687/3688, ids 4350–4352)** — the "발휘시키는" borrow effects (EX3-065, EX5-059/061, BT11-029, BT15-102, BT18-066, EX9-073, BT23-060/101 …) are nine separate implementations; none checks a 【등장 시】 suppression flag on the borrower/target (the 진화 시 counterpart is checked). The natural-trigger path is fixed (bug 4).
4. **EX2-007 as a "digimon"** — generic digimon filters use `category==='digimon'`, EX2-007 is category `digitama` in the data, so most effects cannot target it although the Q&A treats it as a digimon in the battle area (only LM-020's pick was fixed).
5. **Outdated text (P-011 idx 3460–3462, ids 4117–4119)** — the rulings describe the old 「덱 위에서 파기」 wording of ブイドラモン ゼロ; the current card text (트래시→덱 아래) is what is implemented and what 3463/3464/3465 test.
6. **RB1-005/011/020 「A 1장과 B 1장」 with one card satisfying both (idx 3420 …)** — picking the card that is both 「은하준」 and 「감마몬」-mentioning as the *only* card is not offered as a choice (the engine offers the maximal two-card outcome, which is the only sensible one for the player).
