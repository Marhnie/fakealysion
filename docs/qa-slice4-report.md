3. **BT22-007 (Q4859/4860) — 마더 이터.** 원인 3중: (a) 진화원의 「마더 이터」가 3장 미만이면 발휘 불가(공식: 가능한 만큼), (b) 디지타마 카드는 무조건 효과 등장 불가 처리, (c) DP 없음 → 룰체크 파기(17-1-3-2-1)가 [육성] "DP 16000으로 취급"을 무시. 수정: shard64 스크립트 재작성(최대 3장, 있는 만큼), `state.js` playFreeFromZone에서 자체 【등장 시】가 있는 디지타마는 예외, `stackHasDP`가 육성 에어리어 "DP N으로 취급" 문구를 인정.
4. **RB1-009 (Q4080) — "진화원에 명칭에 「감마몬」을 포함하는 카드가 있는 자신의 「감마몬」은 진화 조건 무시, 코스트 3" 미구현.** 수정: `state.js` evolveTargetRestriction에 패턴 추가(정확히 이름이 「감마몬」인 디지몬만, 진화원에 해당 이름 포함 카드가 있을 때).

6. **P-139 (Q4246) / P-144 (Q4259) — 진화원에 "특징 X항체"만 있어도 조건 충족으로 처리.** 공식: 특징이 아니라 「X항체」로 기술된 카드(이름/〈룰〉명칭)만 인정. 수정: `shard43.js` leoSrc, `shard4.js` P-144 noAttack에서 특징 검사 제거(이름 기준 `cardNameIs`).

## 3. 시나리오 해석 오류로 판명된 것 (엔진은 공식 답과 일치)

- Q4124 P-012: `mainAbilityPayable`은 비용만 본다. 육성 에어리어 브이드라몬으로는 실제 발휘 시 테이머가 레스트되지 않으므로 공식 답과 일치 → 발휘 결과로 검증하도록 변경.
- Q4575/Q4180: 대상 선택이 `required:true`(취소 불가)임을 확인하는 방식으로 변경(하네스가 null을 넘긴 것이 원인).
- Q4289: 하네스가 이미 비어 있는 디지몬을 계속 선택한 것이 원인.
- Q4027: 면역 중 기록된 DP-3000은 15-15-5에 따라 면역이 풀리면 적용됨(Q4306/4307과 일치). 기대값 수정.
- Q4242(Lv.- 디지몬): 데이터에 Lv.- 디지몬이 없어 검증 불가 → 시나리오 철회.

## 4. 확인하지 못한 것 (정직한 한계)

- 분류상 T였지만 시나리오를 만들지 않은 약 790건: 표향 시큐리티 계열(Q4370-4379 등, 구현 여부 미확인), 동시 유발 순서(Q4139/4142/4284/4413 등), 소멸 동시 처리·발휘 대기 중 이탈(Q4285/4286/4324), ≪퇴화≫/≪블래스트 진화≫ 타이밍, 리서치가 필요한 조합 카드, 토큰(Q4127·4222), 링크/아프합체(BT21 계열), 파티션/디코드, 오버플로우·표기 위치 상호작용, 「효과를 받지 않는다」 부가 규칙(Q4305-4308, 4394-4397). 일부는 이미 다른 슬라이스/이전 라운드에서 검증됐을 수 있으나 여기서는 확인하지 않았다.
- 어택 진행 중 새 어택 선언 금지(UI/main.js 계층), 누가 결정하는가(플레이어 선택 UI), 발휘 여부 강제(UI)는 Node 하네스로 검증 불가 → N 또는 미구현.
- 통과한 시나리오 중 일부는 약한 단정이다: P-016(Q4128, 보너스 1 이상 확인), EX9-025(Q4778, 1마리만 변경), EX10-025(Q5079)처럼 "부작용 없음"만 보는 것이 있다.
- 하네스는 `lib-driver`와 같은 방식의 ctx(선택 콜백)로 스크립트를 직접 실행한다. main.js의 실제 유발 큐/UI 경로(`pendingEffect` 대기 등)는 통과하지 않는다. 딜레이는 main.js와 같은 순서(`discardForDelay` → 본문 스크립트)로 재현했다.
- 같은 Q&A를 다른 카드가 그대로 반복하는 항목(dupmap)은 대표 카드 1장만 구현한 경우가 있다(예: Raising 진화 코스트 계열은 11장 전부 구현, 표향 시큐리티 계열은 미구현).
- 다른 에이전트가 동시에 `scripts/qa/lib.mjs`를 덮어써서(원본 손실) 이 슬라이스는 `lib-s4.mjs`를 별도 사용한다.
