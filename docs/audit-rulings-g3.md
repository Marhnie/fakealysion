## 방법 및 실제 수행 범위 (정직한 고백)

815개 항목을 전부 동일한 깊이로 검토하는 것은 이번 세션 예산 안에서 불가능했다. 아래 순서로 진행했다:

1. 카드별로 그룹화하여 815개 항목을 훑어보며(skim), "구현이 틀리기 쉬운" 유형(트리거 타이밍, 15-4-4-3 스테일 카드 체크, ≪회피≫/≪세이브≫류 대체 효과, 동시 발동 순서, 색 조건 4-22, DP 계산 순서, 진화원 vs 시큐리티 공유 텍스트 등)을 우선순위로 표시했다.
2. 여러 카드에 걸쳐 **반복적으로 등장하는 공통 패턴**(제네릭 컴파일러/엔진 레벨에서 한 번에 여러 카드에 영향을 주는 것들)을 추려서 실제 코드(src/effects.js, src/state.js)를 직접 확인하거나 scripts/qa/lib-s1.mjs 기반의 임시 시나리오로 실제 동작을 검증했다.
3. 자체 스크립트(shard*.js)가 있는 고위험 카드 중 일부(BT16-051, BT14-081, BT13-007 등)를 표본으로 골라 구현을 코드 리딩으로 확인했다.
4. 815개 항목 중 실제로 "열어서 판단"한 것은 대략 60~80개 수준(공통 패턴 대표 사례 + 표본 카드), 나머지는 skim 수준에 그쳤다.

## 확인 완료 — 이미 올바르게 구현되어 있음 (버그 아님)

아래는 "구현이 틀리기 쉬운 지점"으로 의심했으나, 실제 코드/시나리오 검증 결과 이미 정확히 구현되어 있던 것들이다.

- **"OO의 상대 디지몬이 없는 동안" (공허하게 참 vacuous truth) 계열** (RB1-003/020/022, BT13-047/052, BT14-002 등 다수): `scratch/tmp/audit-g3/probe1.mjs`로 실제 effectiveDP를 검증. 상대 디지몬이 아예 0체일 때도 "액티브 상태인 상대 디지몬이 없는" 조건이 정상적으로 참으로 평가되어 DP+1000이 부여됨을 확인. 버그 없음.
- **"자신이 사용 코스트 N 이상의 옵션 카드를 사용했을 때" 트리거의 코스트 판정** (EX4-024/026/028/030 레나몬/요우코몬/도우몬/쿠즈하몬 계열, id 5487~5502 등): src/state.js:664 부근에 이미 "사용 코스트 = 인쇄된 코스트(또는 손의 카드 자체가 낮아진 코스트); 지불 코스트만 낮아지거나 무료로 사용해도 카운트됨" 이라는 정확한 구분이 구현되어 있고, 정확히 이 Q&A들(구 Q5449-5515)을 인용하는 주석이 있음. 이전 감사에서 이미 수정된 것으로 판단, 재작업 불필요.
- **"OO 발동했을 때" 옵션 카드 트리거가 【시큐리티】/≪딜레이≫ 등 "사용"이 아닌 발동에는 반응하지 않음**: `optionUsed` 이벤트 종류가 실제 "사용(use)" 행위에만 연결되어 있어 정확함.
- **〈룰〉 명칭/카드번호 별칭이 손패·트래시 등 모든 영역에서 유지되는지** (EX4-033 테리아몬 助手, EX4-026 요우코몬 등 다수): `cardNameInfo`/`cardNameHas`가 카드 ID 기반(영역 무관)으로 동작함을 코드 확인. 버그 없음.
- **BT16-051 (돌몬) "소멸 이외로 배틀 에어리어를 벗어나지 않는다"가 DP 0 파기까지 막지는 않는지**: `preventLeave` 훅이 `mode !== 'delete'`인 경우에만 적용되도록 되어 있고, 비-삭제(bounce) 경로에서만 호출됨을 확인. DP 0 룰체크 파기는 별도 경로이므로 정상적으로 파기됨.
- **"진화원에 있는 「X」의 효과 전부를 얻는다" (감마몬 계열: RB1-009/015/023/030, BT15-039, BT16-014/062 등)**: 처음에는 스크립트 컴파일러가 빈 배열을 반환해 "버그"로 의심했으나, 이 패턴은 runScript 오퍼레이션이 아니라 src/state.js:1900 부근의 별도 상시(continuous) 규칙으로 처리되고 있음을 확인. 오탐(false positive).
- **BT14-081 (펜리르가몬) "메모리가 상대측 3 이상이어야 턴 종료"**: `turnEndAt` 훅이 전용 인프라로 존재하며 엔진이 이를 참조함을 확인.

## 실제로 발견하고 수정한 버그

### 1. "서로의 시큐리티를 위에서부터 N장 파기한다" 가 아무 동작도 하지 않음 (제네릭 컴파일러 버그)

- **영향 카드**: BT16-036 카오스몬 (본 그룹 대상, 【상대의 턴 종료 시】 효과), 그리고 동일 문구를 쓰는 BT19-043 루체몬 X항체, BT25-038 토우몬 (다른 그룹 담당이지만 동일 수정으로 함께 해결됨).
- **원인**: `src/effects.js`의 "시큐리티 직접 파기" 컴파일러 패턴(2767번째 줄 부근)이 `(양 측|자신|상대)`만 인식하고 "서로"(mutual, 같은 의미의 다른 표기)를 인식하지 못해, 해당 세그먼트가 컴파일 결과 `[]`(빈 스크립트, 완전 무동작)로 떨어짐. `node scripts/audit-effects.mjs`는 "세그먼트가 어떤 스크립트로든 컴파일됐는가"만 보므로 이 버그를 못 잡음(빈 배열도 "컴파일됨"으로 집계).
- **확인**: `Fx.compileToScript('서로의 시큐리티를 위에서부터 1장 파기한다.')` → 수정 전 `[]`, 수정 후 `[{op:'removeSecurity', who:'self', ...}, {op:'removeSecurity', who:'opponent', ...}]`.
- **수정**: `src/effects.js`에서 해당 정규식에 `서로` 분기 추가, `whos` 배열 판정도 함께 갱신.
- **회귀 검증**: 새 파일 `scripts/qa/qa-audit-g3-mutual-security-trash.mjs` 작성. 두 시나리오 모두 통과:
  1. 양쪽 다 시큐리티가 있으면 각각 1장씩 파기됨.
  2. 한쪽이 0장이어도 효과 자체는 발동하고, 시큐리티가 남아있는 쪽만 파기됨 (BT16-036 공식 Q&A id 2631과 일치).
