# 어택 타이밍 점검 (≪연계≫ / ≪돌진≫ / 레스트 트리거 등)

기준: `rulebook/general_rule_jp_utf8.txt` 11장(어택), 15-8-3(유발형 효과), 16장(키워드).
시나리오: `scripts/qa/qa-attack-timing-1.mjs` (17건). 엔진 변경: `src/state.js`(queueAttackDeclarationTriggers), 신규 `src/cards/shard96.js`, UI `src/main.js`, CPU `src/cpu.js` / `src/cpusim.js`.

## 원인 (사용자 보고)
≪연계≫는 어택 UI 안의 자유 선택 목록으로 구현되어 배틀 결과 전까지 아무 때나 쓸 수 있었다. 룰상 16-24-2 「이 디지몬이 어택했을 때」에 유발하는 유발형 효과이며, 【어택 시】와 같은 타이밍(11-2-8: 선언 후 유발 -> 턴 플레이어 순서 선택 4-3-2)이다. 선택 비용(다른 디지몬 레스트)은 해결 시 묻는다(16-24-3). ≪돌진≫(16-23-2)도 같은 종류인데 리다이렉트 단계의 별도 버튼이었다.

## 수정 내용
1. ≪연계≫ / ≪돌진≫ -> 어택 선언 시 `queueTriggersForStack(..., 'attack')`가 pending(가상 태그 `__연계`, `__돌진`)을 큐에 넣고, 【어택 시】와 같은 큐/순서/확인 UI로 해결. 자유 목록, `api.pa.chain`, CPU의 선행 연계 판단, 돌진 버튼 제거. 「어택 종료까지」 만료(chainRevert)는 유지.
2. 「레스트했을 때」: `declareAttack`이 어택자를 레스트해도 `rest` 이벤트를 내지 않아 (BT2-079, BT9-018, EX3-044 등 약 130장) 반응하지 않았다. 이제 선언의 레스트도 `rest`(cause `attack`, "효과로"가 아님)로 【어택 시】와 동시에 큐에 들어간다. 레스트 없이 어택(noRest)은 발생 안 함.
3. 11-1-4 (해결할 처리가 없어질 때까지 다음 타이밍으로 가지 않음): UI가 선언 트리거 처리 중에도 상대의 대상변경/카운터/블록 버튼을 열어 두었고, 상대 대상변경 후보를 트리거 해결 전 보드로 미리 계산했다. 이제 `settleRedirectTiming`이 대기 효과가 전부 끝난 뒤 후보를 계산하고, 카운터 효과 처리 중에는 블록 단계도 열리지 않는다(렌더 게이트).
4. cpusim / lib-s1: `attackTarget`/`attackOnDigimon` 이벤트를 UI처럼 drain 이전(선언 트리거와 동시)에 발생.
5. BT4-101 「진화원 없는 디지몬에게 어택했을 때 소멸」: 선언 즉시 삭제하던 것을 `__어택소멸` 유발 pending으로 변경(순서 선택 가능).

## DCGO(디지몬 카드게임 온라인) 조사
웹 검색/페이지 확인 결과 얻은 정보는 제한적이다 (설계 문서는 없고 패치 노트와 저장소 구조만 확인).
- DCGO2/DCGO-Card-Scripts: `AttackProcess.cs`, `AutoProcessing.cs`, `CardEffectFactory.cs`/`CardEffectCommons.cs`로 어택 진행/자동 처리/카드 효과 팩토리를 분리. 진행은 [어택 시] -> [카운터 > 블록] -> [성립 확인] 순서. 우리 구조(카드별 스크립트 + 공통 큐)와 방향이 같다.
- 패치 노트에서 보이는 반복 버그: 동일 효과 2개 동시 유발 UI 미지원, "관통이 동점+어택자 보호에서 안 걸림", 해결 중 트래시 메인 사용으로 소프트락. 우리에게 받아들일 점: (1) 같은 효과의 중복 유발을 큐에서 각각 취급, (2) 관통 판정을 "상대 디지몬이 실제로 사라졌는가"로 하는 지금 방식 유지(테스트 16번), (3) 효과 해결 중에는 다른 행동 차단(이번 11-1-4 게이트와 blockIfBusy).
- 카드 스크립트 팩토리 방식처럼 키워드 유발도 카드 데이터가 아닌 공통 팩토리(`queueAttackDeclarationTriggers`)에 두어, 새 키워드는 가상 태그 + `*::__키워드` 스크립트로 추가하는 방식을 표준으로 삼는 것을 권장.
