# 2026-09 전수 감사 — 일본판 공식 룰 탭 + 공식 Q&A 6,673건 재검증

사용자 요청: "효과 적용이 제대로 되었는지 일본판 공식홈페이지의 룰 탭을 모조리 뒤져서 모든 QA와 다시 비교". `https://digimoncard.com/rule/` 의 종합 룰과 카드별 Q&A(FAQ) 전체를 이 시뮬레이터의 구현과 대조했다.

## 0. 방법

- **사이트 재확인**: Q&A 탭은 상품 69개 · 6,673건으로 로컬 캐시(`data/rulings/*.json`, gitignored)와 완전히 일치. 종합 룰 탭은 로컬이 Ver.4.2(2026/08/18)였는데 사이트는 이미 **Ver.4.3**(2026/09/18)으로 갱신돼 있어 새로 받았다.
- **규모 문제**: 6,673건을 한 사람이 전부 같은 깊이로 보는 건 비현실적이라, 상품 파일 단위로 8묶음(750~910건씩)으로 나누고 룰 diff 전담 1개까지 총 9개의 에이전트를 동시에 돌렸다. 각 묶음은 다시 카드별로 위험도를 매겨 우선순위가 높은 것부터 실제 코드 추적·시나리오 검증을 하고, 낮은 것은 이미 검증된 공용 메커니즘으로 훑어보는 식으로 처리했다(3000건 넘게 개별 시나리오를 짜는 건 시간상 불가능 — 대신 "실제로 코드까지 추적한 것 / 훑어만 본 것"을 각 묶음이 정직하게 구분해 보고했다).
- 규모가 큰 묶음은 스스로 다시 하위 조사로 쪼갰다(최대 3단계 재귀). 총 20개 이상의 조사가 돌았다.
- 이 문서는 그 결과를 모은 종합본이다. 개별 묶음 보고서(`docs/audit-rulings-g1/2/3/7/8.md`, `docs/rulebook-v43-changes.md`)는 각자 더 자세한 내용을 담고 있다. 4/5/6번 묶음은 규모가 커서 스스로 하위 조사에 전부 위임했고, 그 하위 조사들의 결과는 이 문서에 통합했다(개별 g4/g5/g6 보고서는 별도로 작성되지 않았다).

## 1. 룰북 Ver.4.2 → 4.3 (docs/rulebook-v43-changes.md 참고)

개정 이력에 적힌 15개 조항과 대조해 완전히 확인. 실질적으로 바뀐 것은 13개, 그중 우리 엔진에 실제 영향이 있던 것은 2개로 둘 다 수정:

1. **2-3-3-3/2-3-3-4**: "≪X≫를 가진 카드"를 참조하는 효과는 **항상 그 키워드를 갖는 카드만** 해당하고, 효과로 임시 획득한 카드는 포함하지 않는다. `hasAlwaysKeyword()`를 새로 만들어 관련 참조 지점에 적용.
2. **15-15-7-4**: "전부 발동"류 강제 효과 안에서도 개별 조건부 비용(하는 것으로)은 여전히 거절할 수 있어야 하는데, 반대로 항상 "예"로 강제하던 부분이 있었다. 제거.

## 2. 확인된 실제 버그 — 종류별 정리 (대부분 수정 완료)

### 2-1. 구조적 문제 — 미해결로 남김

**동시에 여러 대상이 떠날 때 "구제 효과"가 첫 번째만 구한다.** BT19-048, BT25-039, BT24-018 최소 4곳에서 서로 다른 조사가 독립적으로 발견한 같은 패턴. "이 카드를 소멸시키는 것으로 조건에 맞는 자신의 디지몬 전부가 떠나지 않는다"는 효과가, 한 효과로 동시에 여러 마리가 떠날 때 **첫 번째 대상만 구하고 나머지는 그냥 떠난다**(턴 1회 제한이 첫 번째 처리에서 이미 소모됨). 원인은 `deleteStack`이 대상별로 하나씩 순차 호출되고, "동시에 떠나는 묶음"이라는 개념 자체가 없기 때문이다. 고치려면 대량 소멸 호출부들을 "묶음으로 먼저 모아서 판단"하는 구조로 바꿔야 해서, 지금처럼 10개 넘는 에이전트가 같은 파일을 동시에 고치는 상황에서 손대는 건 위험이 크다고 판단해 **의도적으로 보류**했다. 다음 세션에서 전담으로 다뤄야 한다.

관련해서 BT24-018에서 두 개의 세부 버그도 함께 발견(모두 같은 "구제 abilities" 계열, 미수정): "소멸시키는 것으로" 비용이 실제로는 실패(대상이 보호돼 있어 죽지 않음)해도 항상 성공한 것으로 처리됨(Q5599), 그 비용 자체가 여러 장 파기인데 그로 인한 "패가 파기됐을 때" 감시 효과가 여러 번 발동함(15-5-2 위반, BT25-084에서도 같은 문제 발견).

**≪관통≫이 스크립트로 만들어진 강제 배틀에서 시큐리티 체크로 안 이어진다.** EX11-074와 EX13-045/EX12-052/EX13-076 계열에서 두 조사가 독립적으로 발견. 정상적인 어택 흐름의 관통은 `main.js`/`cpusim.js`의 어택 진행 객체(`pa`)에 결과가 기록되는데, "이 디지몬으로 강제로 배틀시킨다" 같은 카드 효과가 별도로 만드는 배틀은 그 객체와 연결이 안 돼 있어 관통이 죽여도 시큐리티 체크가 안 일어난다. 원인은 정확히 특정했지만 main.js/cpusim.js/시험 헬퍼 여러 곳을 함께 고쳐야 해서 **보류**했다.

### 2-2. 수정 완료 — 여러 카드에 영향(공용 로직)

- **`cardMentions()`가 카드의 "특징" 배열을 안 봄** — "기재/기술이 있는 카드" 조건이 이름·효과 텍스트에만 있고 특징으로만 연결된 카드(예: EX13-037이 참조하는 BT18-039, 사용자가 든 예로는 BT6-017)를 놓쳤다. 여러 조사가 각자 다른 카드로 독립 발견 → 이미 수정됨, 재확인 완료.
- **필수 선택을 "대상 없음/취소"로 몰래 건너뛸 수 있음** — 한 문단 안에 필수 절과 선택 절이 섞여 있으면(예: "상대를 레스트시키고, 액티브로 할 수 있다") 전체가 선택 가능한 것으로 잘못 판단됨. `effects.js`의 `destroy`/`grantKeyword` 범용 처리와 `pickStack` 헬퍼 양쪽에서 발견·수정. AD1-024, AD1-006, EX8-073, BT22-074, BT21-061 등에 영향.
- **"합계 DP/코스트/Lv. N까지 소멸" 효과가 매번 강제 선택** — 원래는 첫 픽만 필수고 이후엔 그만둘 수 있어야 하는데 전부 필수로 처리됨(LM-021/ST7-12 등 33장 영향). 수정 완료.
- **Lv.-(레벨 없음) 카드가 "Lv. 합계 N까지" 소멸 대상에 잘못 포함됨** — BT17-051에서 발견, 관련해 BT18-019의 같은 계열 조건도 방어적으로 수정.
- **시큐리티 재공개 위치 추적 오류** — 같은 카드가 서로 다른 깊이에 여러 장 있을 때, 다시 뒤집으면 실제 다음 위치가 아니라 같은 카드를 또 세는 문제. `secFlipTopFaceUp` 수정.
- **"효과로 디지몬을 등장 못 함" 잠금** — (a) 잠근 대상이 아닌 **다른 플레이어의 효과**까지 막던 문제(누구 필드인지로 잘못 판정), (b) 배틀 에어리어에만 걸리고 **육성 에어리어에는 안 걸리던 문제**(BT23-014 Q6249). 둘 다 수정.
- **《돌진》 대상 변경 시 사람 화면에서 대상이 하나도 안 보임** — pickStack의 player 필드를 공격자로 잘못 넘겨서 화면 렌더러가 상대 쪽 대상을 못 찾음. 근본 수정 + 화면 렌더러에 안전장치 추가.
- **진화 전/후 이름이 겹치는 카드(그레이몬⊂메탈그레이몬 등, 2천 쌍 이상)에서 이펙트가 엉뚱한 대상에 뜸** — 화면 연출용 이름 매칭 로직 수정.
- **"이 효과로 소멸하지 않았을 때" 조건이 대체 효과(회피/수호)로 다른 카드가 대신 죽었을 때도 "소멸했다"고 오판** — `destroy` 연산의 실제 반환값을 추적하도록 수정.
- **"서로의 시큐리티를 파기" 문구에서 "서로의"를 인식 못 해 아무 일도 안 일어남** — BT16-036 외 BT19-043, BT25-038도 영향, 수정.
- **≪퇴화 N≫(단일 선언, N≥2) 카드가 매수 선언 없이 항상 최대치 파기** — EX11-045에서 발견. (주의: "~마다 ≪퇴화 1≫"을 반복하는 카드는 공식 룰링상 선언 단계가 없는 게 맞아서, 처음에 잘못 넣었다가 룰링 재확인 후 되돌렸다.)

## 3. 확인만 하고 문제없었던 것 (표본)

효과 즉시성/유발 분리, 15-4-4-3 카드 교체 시 대기 무효화, DP 0 룰체크 지연(전체 효과가 끝날 때까지), 시큐리티 효과 최우선 처리, 표면 시큐리티(공개 유지·체크·셔플 시 뒤집힘), 링크 카드는 진화원이 아님, 4-22 색 조건과 육성 에어리어 참조 확장, 진화원 vs 시큐리티 텍스트가 같은 인쇄란을 공유하는 다수 카드, 테이머를 디지몬으로 취급하는 진화 계열 전반, 관통의 즉시성(나중에 DP가 떨어져도 이미 유발된 체크는 취소 안 됨), 코스트 할인 스택 순서, 동시 유발 시 턴 플레이어 우선 등. 상당수가 이미 이전 세션들에서 공식 Q&A 번호를 주석에 남기며 고쳐져 있었고, 이번 감사가 그걸 다시 한번 확인해 줬다.

## 4. 정직하게 밝히는 한계

- **전수 검사가 아니다.** 6,673건 중 실제로 코드까지 추적하거나 시나리오를 짠 것은 다 합쳐도 절반이 안 된다. 나머지는 "이미 검증된 공용 메커니즘의 반복"으로 판단해 훑어만 봤다. 놓친 버그가 더 있을 수 있다.
- **동시-이탈 구제 문제와 관통 전파 문제**는 원인을 정확히 알지만 고치지 않았다 — 다음에 전담으로 다뤄야 한다.
- **EX6-006**(할인 -4 대상이어도 -3 선택 가능해야 함)은 공용 할인 선택 UI 구조를 바꿔야 해서 보류했다.
- 아루다몬(BT7-014/BT17-014)의 "특징을 가진 동안" 판정을 진화원 카드 기준으로 구현했는데, 이 카드 자신이 실제로 그 특징을 언제 갖는지 원문 카드로 재확인하지 못했다.
- 사람이 두는 화면(UI)에서 직접 재현해 본 것은 이번에 고친 것 중 극히 일부뿐이고, 나머지는 Node 시나리오로만 확인했다.

## 5. 검증

매 수정마다 문법 검사와 관련 시나리오를 돌렸고, 마지막에 전체 `test-all.mjs` 24단계(문법 154개 파일, 효과 커버리지 100%, 소크 60판 오류 0, 퍼즈 200판 0, CPU/덱/스냅샷/구경 모드 등)를 통과했다. 새로 추가된 회귀 시나리오 파일이 30개 이상이다.
