# 룰 감시자(rule-oracle) 보고

`scripts/rule-oracle.mjs`(+ `rule-oracle-fx.mjs`)는 CPU끼리 대전의 모든 단계에서 룰북 규칙 위반 여부를 엔진 로직과 무관하게 검사하는 독립 감시 도구입니다. 훅은 `src/cpusim.js`에 있고, 훅이 없으면 동작이 달라지지 않습니다.

## 구성
- 검사 114개 (규칙 번호 태그). 실행: `scripts/run-oracle-parallel.mjs`, 분류/재현: `oracle-replay.mjs`, `oracle-trace.mjs`, `oracle-card.mjs`, `oracle-script.mjs`.
- 회귀 시험: `scripts/test-oracle-regress.mjs` (통과).

## 실행 규모
- 개발 중 약 3만 판. 마지막 전체 실행: 6,000판, 검사 평가 약 1,040만 번, 이어서 깨끗한 2,400판.
- 진화 조합 1,120만 개, 조그레스 조합 1,910만 개를 카드 인쇄 조건과 전수 비교: 불일치 0건.

## 발견 → 원인 → 수정
| # | 발견 | 원인 | 수정 |
|---|------|------|------|
| 1 | 진화원 효과가 엉뚱한 스크립트를 실행 (LM-003, EX5-029, BT15-064 등 약 14장) | `lookupCardSpecific`가 같은 태그의 카드 자신 효과 스크립트를 진화원 효과에도 사용 | `inherited` 플래그를 받아 구분 (cpusim/main/fuzz/lib-driver 호출부 수정) |
| 2 | 《아머 퍼지》로 살아남은 디지몬이 DP≤0으로 필드에 남음 | `ruleCheckDP`가 한 번만 실행 | 안정될 때까지 반복 |
| 3 | 조용한 DP 변화 뒤에 DP≤0 룰 체크가 실행되지 않음 (사라지는 DP 보너스, 룰 15-15-5-2 DP 감소) | 룰 체크 트리거 누락 | 시큐리티 체크 단계·룰 체크 정리·화면 그리기 시작·cpusim에 검사 추가 |

그 외 위반은 감시자 쪽 오탐이라 감시자를 다듬었습니다.

## 한계
- CPU 대전은 디지크로스, 버스트 진화, 앱합체, 링크를 하지 않아 감시자가 보지 못합니다(퍼저 `scripts/fuzz.mjs`가 대신 다룸).
- 효과 결과 사후조건 검사는 한 문장짜리 템플릿 약 20개에만 있습니다.
