## 깨끗하다고 확인된 항목 (음성 결과)

- **DEAD 0종**: 초기 집계의 39종은 전부 엔진이 큐잉 단계에서 스스로 평가하는 조건(`상대의 디지몬에게/플레이어에게 어택했을 때`, `배틀 이외로 소멸하고 있었다면`), `skipTrigger` 훅(BT14-048), `발휘하지 않음` 억제 로그를 오라클이 몰랐던 거짓 양성이었음 → 오라클에 반영 후 0.
- **DOUBLE 사실상 0종**: 같은 카드 여러 장(진화원 안 동명 카드, 테이머 3장)은 각각 별개 효과이므로 정상. (EX2-056 오유민 3장 → 3회 큐잉은 정상.) 남는 1건(P-080 래브라몬 부여 효과 2회)은 3만 게임 중 1회로 재현 안 됨.
- **ONCE-VIOLATION 사실상 0종**: 로그만 남기고 코스트를 못 낸 `costGroup` 을 "발동"으로 센 거짓 양성을 제외하면 〔턴에 N회〕 상한 초과는 3만 4천 게임 중 3건(EX8-032/BT3-002/BT20-022 진화원, 각 1회, 180게임 재시도로도 재현 불가 — 턴 중 진화원 동명 카드 수 변화 추정). (참고: `cpusim.drain` 은 처음엔 main.js 의 15-4-4-3 / 〔턴에 1회〕 게이팅이 없었으나 작업 중 다른 에이전트가 미러링함 — 센서스는 그 이후 상태를 측정)
- **감시형 직접 프로브(`scripts/census-watch-probe.mjs`)**: 엔진의 자체 파서가 이해하는 감시 세그먼트 481개에 대해 최소 보드를 만들고 실제 `emitGameEvent` 를 발사 → 474개 큐잉, 미큐잉 7개는 모두 카드 고유 훅(`events`)이 자기 조건(레스트한 디지몬만, NSp 특징만 등)으로 걸러낸 정상 동작.
- **ERRORED 0건**, 게임 중 예외 0건.
- SILENT 상위 항목은 대부분 조건 미충족(무변화), `afterBattle`(배틀 종료 시 예약), `attackNow`(cpusim 의 startAttack 은 no-op) 등 시뮬레이터 특성이며 엔진 버그 아님.
- MANUAL 의 《딜레이》 항목은 `src/main.js runPendingScript` 의 딜레이 전용 경로(`delayBulletPlan`)가 처리하는 UI 전용 흐름이라 헤드리스 cpusim 에서만 수동으로 보임(CPU 가 딜레이 옵션을 안 씀).

```
node scripts/census.mjs --from 0 --to 367 --games 8 --minutes 9 --seed 1 --out c0.json < /dev/null    # 12개 워커로 분할 실행
node scripts/census.mjs --merge c*.json --out merged.json < /dev/null
node scripts/census-report.mjs merged.json findings.txt > docs/effect-census.md < /dev/null

```
덱 생성: 카드 1장당 4장 + 진화 라인(아래 레벨 사슬 최대 2종 × 3~4장, 위 레벨 1단계) + 알 + 같은 색 테이머/옵션/서포터, 게임의 1/3은 미러(양쪽 같은 덱), 나머지는 랜덤 단색 덱. 포커스 카드는 합법 액션이 있으면 60% 확률로 강제 플레이/사용/진화(CPU 가 비싼 옵션을 거의 안 써서 옵션 134장이 한 번도 발동되지 않던 문제 해결).
