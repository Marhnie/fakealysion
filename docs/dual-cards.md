구현: `src/state.js` (isDual / optionView / queueTriggersFor / artsDigivolve / settleLimbo), `src/cards/shard140.js` (아츠 진화 처리),

  글꼴 인코딩 때문에 텍스트 추출이 되지 않아(pdftotext 결과가 깨짐) **4.3에서 듀얼 관련 조문이 바뀌었는지는 확인하지 못했다.**
- 공식 Q&A (`data/rulings/all.json`, 저장소에 넣지 않음)의 デュアル/アーツ 관련 질문 약 20건을 읽고 아래 동작의 근거로 삼았다 (문구는 옮기지 않음).

  옵션 쪽 효과 텍스트는 한국어 데이터의 "진화원 효과" 칸(`sourceEffect`)에 들어 있다. 총 19종:
  BT25-043/057/085/104, ST23-09, ST24-07, EX12-018/033/052, BT26-031/032/033/050/056/057/075/080, EX13-065/066.
- **데이터 결측**: `dualFaceCost`가 없는 카드는 EX12-018, EX12-033 (그리고 색은 EX12-018/033/052, BT26-031/033 등). 추정값을 쓴다: 코스트 5 (다른 Lv.6 듀얼의 실제 값이 4~6),
  색은 디지몬 쪽 첫 번째 색. 실제 카드와 다를 수 있다 — 원본 데이터가 채워지면 `data/cards_full.json`의 `dual` 값만 고치면 된다 (`scripts/build-cards.mjs` 참고).

## 2. 룰 요약 (내 말로)

1. **정의 (4-6)**: 듀얼 카드는 디지몬 카드이면서 옵션 카드이다. 카드의 특징 줄 위쪽이 "디지몬 쪽", 아래쪽이 "옵션 쪽"이다.
   디지몬으로 참조할 때는 디지몬 쪽만, 옵션 카드로 참조할 때는 옵션 쪽만 본다. 디지몬 쪽 효과는 디지몬의 효과, 옵션 쪽 효과는 옵션 카드의 효과다
   (그래서 「디지몬의 효과를 받지 않는다」인 디지몬에게도 옵션 쪽 【메인】이 통한다).
2. **실행할 때 선언 (4-6-2)**: 패의 듀얼 카드는 "디지몬 쪽으로 진화"하거나 "옵션 쪽으로 사용"한다. 디지몬 쪽에는 등장 코스트가 없으므로 **패에서 직접 등장시킬 수는 없다**
   (효과의 「등장 코스트 N 이하」 조건도 만족하지 않는다).
3. **에어리어에 있는 듀얼 카드는 디지몬이다 (4-6-3)**: 진화로 올라간 듀얼 카드는 디지몬으로만 취급하고, 「배틀 에어리어의 옵션 카드를 파기한다」 효과의 대상이 아니다.
4. **옵션으로 사용 (9-1)**: 색 조건(4-22)을 옵션 쪽 색으로 판정하고, 옵션 쪽에 인쇄된 사용 코스트를 지불한다(예: BT26-033 "시큐리티 1장당 사용 코스트 +1"). 《사용조건《…》》이 있으면 지정 카드가 있을 때 색 조건을 무시할 수 있다.
   사용한 카드는 【메인】 효과가 해결될 때까지 **어느 영역에도 속하지 않는다 (9-1-4)**. 해결 직후 (사이에 다른 효과/룰 체크가 끼지 않고) 아직 어느 영역에도 없으면 파기한다 (9-1-5).
5. **아츠 진화 (4-20)**: 위 9-1-5의 파기를 **대체**하는 처리다. 파기하는 대신, 에어리어에 있는 자신의 카드 1장을 그 듀얼 카드로 **코스트 없이** 진화시킬 수 있다.
   - 진화 조건(레벨/색/특수 〔진화〕 줄)은 그대로 만족해야 한다. 공식 Q&A: 사용한 카드는 이미 패의 카드가 아니므로 "패의 카드라면 조건을 무시" 같은 효과로 조건을 면제받을 수 없다.
   - 진화로 새 카드가 올라가므로 이전 카드의 【등장 시】 등 아직 발휘 전이던 효과는 사라진다 (Q&A: EX13-065/066).
   - 이 진화에서 발생한 디지몬 카드의 【진화 시】는 정상적으로 발동한다. 어택 중인 디지몬으로 진화했다면 그 디지몬의 【어택 시】는 발휘할 수 없다 (Q&A: BT25-057, EX12-018).
   - 옵션 【메인】으로 DP가 0이 된 디지몬은, 카드가 파기되거나 아츠 진화가 끝난 **뒤** 룰 체크로 소멸한다 (그 뒤에 【소멸 시】와 아츠 진화 카드의 【진화 시】가 동시 발동).
6. **BT25-104 "옵션 쪽의 【메인】 효과를 1개 발동한다"**: 옵션 카드의 「사용」이 아니라 효과만 직접 발휘하는 것이며, 그 효과는 옵션 카드의 효과다. 사용 코스트/색 조건/아츠 진화는 없다.
7. **시큐리티 (Q&A: BT26-075)**: 시큐리티에서 체크된 듀얼 카드는 디지몬 카드이자 옵션 카드로 취급하지만, 디지몬 쪽의 【시큐리티】 효과는 디지몬의 효과로 발휘한다.
   데이터의 19종에는 옵션 쪽 【시큐리티】 줄이 없어 옵션 쪽 처리는 필요 없다.
8. **덱 구축**: 메인 덱의 (디지몬) 카드로 센다. 같은 카드 넘버 4장 제한 등은 일반 카드와 같다. 별도의 듀얼 전용 제한은 룰 문서에서 찾지 못했다.

## 3. 엔진 구현

| 주제 | 구현 |
|---|---|
| 카드 데이터 | `cards_full.json`의 듀얼 카드에 `dual: { cost, colors }`. `loadData()`가 옵션 쪽 텍스트를 `inheritedKo` → `optionKo`로 옮겨(듀얼 카드는 진화원 효과가 없다) 진화원 효과·【메인】 능력 목록에 섞이지 않게 한다. |
| 옵션 시점 | `S.optionView(id)` = category 'option', 옵션 쪽 이름/코스트/색/텍스트를 가진 뷰. `optionColorOk`, `optionBaseCost`, `optionCostOptions`, `queueTriggersFor('use')`, CPU가 이걸 쓴다. `S.isOptionLike(id)` = 옵션 카드 또는 듀얼(「옵션 카드를 사용」 필터). |
| 패/덱/트래시/시큐리티 | 카드 종류는 그대로 'digimon' (덱·패·트래시·시큐리티 어디서든 디지몬 카드). 옵션으로 쓸 때만 옵션 뷰. 시큐리티 체크는 디지몬으로 처리. |
| 등장 | `playDigimonFresh`가 듀얼 카드를 거부. 드래그/버튼/CPU는 듀얼을 "옵션으로 사용"으로 보낸다. 「등장 코스트 N」 필터(`matchesFilter`)는 듀얼(코스트 없음)을 제외. |
| 사용 후 처리 | 사용한 듀얼 카드는 `pl.limbo`(어느 영역도 아님, 9-1-4)에 둔다 → 옵션 【메인】이 트래시 카드를 고르는 효과에 자기 자신이 잡히지 않는다. 【메인】이 해결(`resolvePending`)되면 바로 앞자리(depth 999, 순서 선택 창 없이)에 `__아츠진화` 항목이 생기고 (`shard140.js`), 처리 후 카드가 limbo에 남아 있으면 트래시로 보낸다(`settleLimbo`). |
| 아츠 진화 | 후보 = 육성/배틀 에어리어의 디지몬/디지타마 중 `E.evolutionMethods`/`canEvolveAny`로 이 듀얼 카드에 진화 가능한 것 (버스트/어플 합체 제외). 후보 1개면 예/아니오, 여러 개면 선택(취소 = 그냥 파기). 실행은 `S.digivolve(…, cost 0, 'arts')` — 드로우, 【진화 시】, DP 룰 체크가 정상 진행. |
| 효과 종류 | 옵션 쪽 대기 항목은 `optSide` 플래그 → `fxSourceOf`가 옵션 카드 효과로 취급 (「디지몬의 효과를 받지 않는다」 면역 무시). BT25-104는 `ctx._optSide`. |
| 진화 조건 버그 | 〔진화〕 「등장 코스트 12의 「케레스몬」」(BT26-032/080)이 파싱되지 않아 아무 디지몬에서나 진화 가능했던 것을 `engine.js`에서 수정. |
| 덱 검사 | `decktools`: 샘플 핸드 시뮬레이션에서 듀얼은 옵션 카드로도 센다, 통계/검색 텍스트에 옵션 쪽 포함. 옵션 쪽 색 조건은 듀얼 카드 자신(디지몬)이 필드에 있으면 충족되므로 별도 경고는 두지 않았다. 덱 합법성은 일반 디지몬 카드와 동일. |
| CPU | `cpu.js`: 듀얼은 등장 후보에서 제외, 옵션 후보로 평가(옵션 쪽 텍스트로 가치 계산). 진화 후보는 디지몬 쪽으로 기존 경로. 아츠 진화 확인창은 기존 `confirmEffect`/`pickStack` 응답. `cpusim.js`는 그대로(옵션은 `useOptionCard`). |
| UI | 패에서 듀얼 선택 → "▶ 옵션으로 사용" 버튼, 전장 빈 곳 탭/드롭도 옵션 사용. 카드 위에 드롭/탭하면 기존처럼 디지몬 쪽으로 진화. DB 미리보기·정보 패널에 옵션 쪽 블록. 사용 후 "아츠 진화" 확인/선택 창. |
| 되돌리기/리플레이 | 스냅샷은 안정 상태(대기 효과 없음)만 저장하므로 limbo는 항상 비어 있다. limbo/`__아츠진화`는 `structuredClone` 가능한 순수 데이터다. |

## 4. 알려진 한계 / 추정

- 위의 옵션 쪽 코스트·색 결측(EX12-018/033 등)은 추정값이다.
- 옵션 쪽 【메인】이 "패의 카드를 그 듀얼 카드 자신에게 진화"시키는 특수 효과와의 상호작용, 테이머의 아츠 진화(테이머 진화 조건)는 구현하지 않았다.
- 아츠 진화 후보에서 진화 코스트를 바꾸는 효과(진화 코스트 -N 등)는 코스트가 0이므로 적용하지 않는다.
- BT25-082 (블랙테일몬) 등 "진화 조건을 무시하고 진화"시키는 효과가 아츠 진화와 함께 쓰이는 경우(Q&A 6390)는 해당 카드 스크립트가 처리하는 범위까지만 확인했다.
- Ver.4.3 본문 미확인 (위 1항).
