## 새로 발견하여 수정한 버그

### BT6-111 알파몬 — 【어택 시】 가변 코스트 지불량에 비례한 DP 상승이 미구현

- **증상**: 카드 텍스트 "코스트를 5까지 지불하는 것으로, 이 턴 동안 이 효과로
  지불한 코스트 1마다 이 디지몬의 DP를 +1000 한다"는 "0~5 중 원하는 만큼 지불 →
  지불량×1000만큼 DP 상승"이어야 하는데, 범용 컴파일러(`src/effects.js`)에는
  "최대 N까지 지불 → 지불량에 비례해 효과 배율" 패턴에 대한 지원이 전혀 없어서,
  실제로는 `manualCost`(플레이어에게 "지불했습니까?"만 확인)로 대체되고 DP는
  항상 고정 +1000만 적용되고 있었습니다. 즉 3을 지불해도 DP는 1000만 오르는 버그.
  (`node --check`/실제 실행으로 `Fx.compileToScript()` 산출물을 직접 검사해 확인.
  이 패턴("코스트를 N까지 지불...1마다")을 쓰는 카드는 전체 DB에서 BT6-111이
  유일해서, 범용 컴파일러 확장보다 카드 단위 수정이 맞다고 판단했습니다.)
- **수정**: `src/cards/shard1.js`에 `SCRIPTS['BT6-111::어택 시']` 전용 스크립트를
  추가. `S.canPayCost`로 지불 가능한 최대치(최대 5)를 구하고, `multipleChoice`로
  0~max 중 실제 지불액을 선택받아 `S.spendMemory`로 실제 코스트를 지불한 뒤,
  지불액×1000만큼 `S.modifyDP`로 이번 턴 동안 DP를 올리도록 정정.
  (참고: 이 카드의 별도 세그먼트인 【어택 종료 시】 메모리 +2는 애초에 태그별로
  독립 컴파일되어 정상 동작하고 있었음 — 처음에는 전체 텍스트를 한 번에
  `compileToScript`에 넣어 테스트하다 두 세그먼트가 뒤섞여 보였는데, 실제 런타임은
  `lookupCardSpecific(cardId, tags, ...)`으로 태그별로 분리해 컴파일하므로 문제
  없음을 재확인함.)
- **회귀 테스트**: `scripts/qa/qa-audit-g1-bt6-111.mjs` (3개 시나리오: 3 지불 시
  DP+3000, 0 지불 시 DP 불변, 5 지불 시 DP+5000 — 모두 이 카드의 별도
  【어택 종료 시】 메모리+2와의 합산까지 고려해 검증). `node
  scripts/qa/qa-audit-g1-bt6-111.mjs`: 3 scenarios, pass 3, fail 0.
- **주의**: 이 버그는 제 917개 룰링 항목 중 어떤 공식 Q&A로도 직접 지적되지
  않았습니다 (BT6-111의 5개 Q&A는 전부 【세큐리티】/【어택 종료 시】 타이밍에
  관한 것이었음). 코드를 추적하다 우연히 발견한 것이라 밝혀둡니다.
