대상: 돌(p1, 사람) vs 후디에(p2, CPU). 사용자가 무엇이 이상했는지 적지 않았으므로, 로그/보드를 룰 눈으로 읽어 가장 그럴듯한 이상 현상을 찾았다.

로그는 최신이 위(역순). 시간순으로 정리.

### 근본 원인 (확정)
세이브의 `state` 를 열어 보면 `_rcDepth = 1`, `_fxSrc = {p2, BT23-101}`, `_fxOp = "s6_run"`, `_rcPending` 에 p1 아이스몬(u28)·p2 스택 등 13건이 쌓여 있었다.

- `runScript`(effects.js)는 실행 동안 `_rcDepth++` 하여 룰체크(17-1-2-2: 효과 처리 중에는 룰체크를 하지 않음)를 미루고, `finally` 에서 `--_rcDepth` 후 `flushRuleChecks` 를 한다.
- 후디에몬(BT23-101) 【등장 시/진화 시】 러너가 **끝나지 않고 멈췄고**(약 2분 후 CPU 워치독이 "멈춘 효과 처리 재시도"), 재시도는 러너 플래그만 초기화하고 **멈춘 옛 러너가 쥔 `_rcDepth`/`_fxSrc` 는 그대로 남겼다.** 재시도된 두 번째 실행이 DP -15000 을 적용했지만 깊이가 1 남아 있어서 `ruleCheckDP` 가 `_rcPending` 에만 쌓고 끝났다. 이후 `flushRuleChecks` 는 깊이가 0 이 되어야만 실행되므로 **게임이 끝날 때까지 어떤 DP 0 룰체크도 실행되지 않는 상태**가 되었다.
- 이 상태가 세이브/자동저장/되돌리기 스냅샷에 그대로 들어가 (`restoreState` 가 `_rcDepth` 를 복원) 불러와도 유지된다.
- 보드에서 보인 증상: DP 0 이하(-10000)인 마그네틱드라몬이 살아 있고, 프래그먼트도 발동하지 않았다(소멸 자체가 시도되지 않았으므로 대체 효과 프롬프트가 뜨지 않음). 진화원이 2장뿐이라 정상이라면 프래그먼트 《3》 없이 그대로 소멸했어야 한다(진화원 부족, 16-37-1/-3).
- 같은 저장 상태를 Node 에서 불러 마그네틱드라몬을 복원해 DP -3000×3, -15000 을 주면 재현된다: `DP -10000 alive`, 로그에 "DP 0 이하 — 룰체크로 소멸" 이 없음. `_rcDepth` 를 0 으로 만든 새 게임에서는 즉시 소멸(재현 스크립트 = `scripts/qa/qa-fragment-audit.mjs` Q15).

멈춘 이유 자체(후디에몬 러너가 무엇을 기다렸는지)는 헤드리스로 재현되지 않았다 (아래 (d)).

## (c) 수정한 버그 / 남은 것

수정:
1. **러너 상태 누수로 룰체크가 영구 지연** (근본 원인, 위 (a)).
   - `src/snapshot.js` `restoreState`: 불러오기/되돌리기 시 `_rcDepth=0, _fxSrc/_caster/_fxOp=null, _ownBusy/_dp0Delete=false` 로 초기화 (새로 복원된 상태에는 실행 중인 스크립트가 있을 수 없음). 이 세이브를 다시 불러오면 `_rcPending` 이 다음 렌더에서 처리되어 남아 있는 DP<=0 스택이 정리된다.
   - `src/main.js` `retryPending`(워치독 재시도) : 옛 러너를 버릴 때 `healLeakedFxState()` 로 `_rcDepth`/`_fxSrc` 를 정리하고 룰체크를 즉시 수행.
   - `src/main.js` `renderInner` -> `healIdleLeak()` : 러너/선택창/대기 효과/어택/대체 프롬프트/연출이 모두 없는데 `_rcDepth>0` 이 3초 이상 지속되면 누수로 보고 같은 정리를 수행 (안전망).
2. 프래그먼트가 뒷면 진화원을 파기할 때 `s5fd`(뒷면 개수)를 갱신하지 않아, 남은 앞면 카드가 뒷면으로 취급될 수 있었다 (`src/state.js` `trySurviveByKeyword`).
3. `《퇴화》`가 뒷면 진화원을 새 최상단으로 올릴 수 있었다 (`retreat`); "진화원 N장 파기" 계열 코스트 필터가 뒷면 카드 정보를 참조했다 (`surviveCost`).

남은 것(미해결):
- 후디에몬 러너가 **왜 멈췄는지**는 특정하지 못했다 (아래 (d)). 위 수정은 결과(룰체크 지연)를 막지만 멈춤 자체(2분간 CPU 효과 대기)는 그대로 발생할 수 있다.
- 프래그먼트로 파기한 진화원은 `sourcesTrashed` 이벤트를 내보내지 않는다 (「진화원이 효과로 파기되었을 때」 감시 카드, 예: EX8-051 상속 효과가 프래그먼트 비용에도 반응해야 하는지). 카드 텍스트가 명시하지 않아 손대지 않았다.
- 프래그먼트 후보 조합은 12개로 잘린다 (진화원이 12장을 넘는 경우 일부 조합은 선택지에 없음). 실전에서는 거의 없음.
- 헤드리스 CPU(`cpusim.js`)는 이미 `_rcPending` 를 처리하지만 러너 누수 자체의 자가복구는 브라우저(`main.js`)에만 넣었다.

## (d) 검증하지 못한 것 (정직한 기록)
- 사용자가 실제로 본 현상은 알 수 없다. 위 "DP -10000 마그네틱드라몬이 죽지 않음"이 가장 유력한 후보일 뿐이다 (프래그먼트 미발동 + DP 0 미소멸을 한꺼번에 설명하는 유일한 원인).
- 후디에몬 【진화 시】 러너가 멈춘 정확한 원인: Node 헤드리스(`drain` + 기본 선택)에서는 같은 카드 구성이 멈추지 않았다. UI 프롬프트(`ctxChoose`)/CPU 선택 경로에서 대기했을 가능성이 높지만 확인하지 못했다.
- 브라우저 UI 에서 `healIdleLeak` 의 3초 타이머와 프롬프트 표시를 직접 눈으로 확인하지 않았다 (Node 시나리오와 문법 검사, `test-cpu`, `soak` 만 수행).
- 로그 창이 마지막 250줄이라 턴 1~4 이전의 상세는 정보가 없다 (게임 전체 로그는 포함되어 있었다).
