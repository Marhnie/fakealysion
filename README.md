# 디지몬 카드게임 시뮬레이터

브라우저에서 마우스(드래그 앤 드롭)만으로 플레이할 수 있는 디지몬 카드게임(Digimon Card Game) 2인 대전 시뮬레이터입니다. 실제 카드 데이터베이스와 공식 종합룰북을 기반으로 게임 규칙과 카드 효과를 최대한 자동화하는 것을 목표로 합니다.

프레임워크 없이 순수 JS(ES 모듈)로 작성되어 있고, 빌드 과정 없이 정적 파일만으로 동작합니다.

## 실행 방법

Node.js가 설치되어 있으면:

```bash
npx serve .
```

이후 안내되는 주소(기본 `http://localhost:3000`)로 접속하면 됩니다. Claude Code의 미리보기 도구를 쓰는 경우 `.claude/launch.json`에 등록된 `digimon-sim` 설정(포트 5588)을 그대로 사용하면 됩니다.

## 주요 기능

- **드래그 앤 드롭 플레이**: 손패 카드를 배틀 에어리어나 자신의 디지몬 위로 드래그하면 등장/진화, 옵션 카드 사용까지 코스트 자동 계산으로 처리됩니다. 공격도 상대 배틀 에어리어로 드래그해서 선언합니다.
- **카드 효과 자동화**: 카드 원문(【등장 시】/【진화 시】/【소멸 시】 등)을 파싱해 트리거를 큐잉하고, 자주 나오는 패턴은 자동으로 해석·적용합니다. 진화원(進化元)으로 깔린 카드의 상시 효과(계승 효과)도 함께 계산합니다.
- **시큐리티 배틀 시각화**: 공격/디지몬 배틀/시큐리티 체크 결과를 카드 대 카드 비교 UI로 보여줍니다.
- **3D 테이블탑 뷰**: CSS 3D perspective로 필드를 기울여, 실제 테이블에 마주 앉아 카드를 놓는 듯한 느낌을 줍니다.
- **덱 빌더**: 카드 검색·구성·저장이 가능한 별도 화면(4장 제한/메인 50장/디지타마 5장 등 공식 구성 규칙 검증 포함).
- **공식 한글 용어**: UI 문구를 한글판 공식 명칭(육성 페이즈, 시큐리티, 진화원 등) 기준으로 맞춰뒀습니다.

## 모바일(터치) 조작

드래그 없이 탭만으로 전부 플레이할 수 있습니다 (PC의 드래그&드롭도 그대로 동작). 세로/가로 화면 모두 지원.

- **카드 탭** = 선택 + 하단 시트에 카드 정보 표시 (시트의 글을 탭하면 펼침, ✕로 선택 해제)
- **등장/사용**: 핸드 카드 탭 → 시트의 `▶ 등장` 또는 초록색으로 빛나는 배틀 에어리어 빈칸 탭
- **진화·버스트·어플합체**: 핸드 카드 탭 → 초록 테두리로 표시된 내 디지몬(육성 에어리어 포함) 탭 (진화 방법 선택창이 뜨면 탭으로 선택)
- **링크**: 핸드 카드(또는 배틀 에어리어의 내 디지몬) 선택 → 대상 디지몬의 초록색 🔗 배지 탭
- **조그레스/DNA (룰 8-2)**: 〔조그레스〕가 있는 핸드 카드를 탭(또는 드래그)하면 재료가 될 수 있는 내 디지몬이 보라색으로 빛나고(`🧬재료`), 시트에 `🧬 조그레스 진화 (N조합)` 버튼이 생김. 버튼·재료 탭·재료 위로 드롭 중 무엇이든 조합 선택창(`X + Y → Z`, 코스트·메모리 변화 표시)이 열리고, 조합의 큰 버튼을 누르면 진화. 재료를 먼저 탭하면 `🧬 조그레스 가능: <핸드 카드>` 버튼이 뜸. 조건이 안 맞으면 이유(필요 조건)가 토스트로 표시됨. (기존 `조그레스 상대 선택` 방식은 제거됨)
- **공격**: 액티브 내 디지몬 탭 → `⚔ 공격`(대상 목록에서 선택) 또는 상대의 빨간 테두리 디지몬/상대 헤더(P1·P2 이름줄)를 직접 탭
- **딜레이/트레이닝/⚡메인**: 해당 디지몬 탭 → 시트의 버튼
- **육성 페이즈**: 디지타마 더미 탭 = 부화, 육성 에어리어 카드 탭 = 배틀 이동
- **덱 빌더**: 카드 탭 = 1장 추가, 내 덱의 카드 탭 = 1장 제거, `내 덱 ↓`로 덱 목록으로 이동
- 상단 바는 턴/페이즈/메모리·다음 페이즈·패스·투항, 로그는 오른쪽 아래 `◀ 로그` 버튼

## 카드 효과 자동화 현황

카드 원문을 규칙 기반으로 컴파일해 적용하는 방식이라, 세트별로 커버리지가 다릅니다. 현재 **BT1, EX1, ST1, ST2, ST3**는 텍스트 컴파일 기준 자동 처리가 거의 완비되어 있고, 그 외 세트의 카드는 자동 처리가 안 되는 효과 문구가 있으면 화면 하단 "발동 대기 중인 효과" 목록에 원문 그대로 표시되며, "범용 도구" 패널로 수동 처리할 수 있습니다.

링크(링크)·오버플로우(오버플로우) 등 최신 메커니즘도 엔진에 구현되어 있습니다. 다만 아츠진화(DUAL 카드)는 현재 카드 데이터베이스에 실제로 존재하는 카드가 없어 검증되지 않은 스텁으로만 남아있습니다.

## 효과 가시화 (누구의 효과가 무엇을 했는지)

- 효과 처리 중 남는 로그에는 출처(카드·소유자·【태그】)가 붙고, 로그에서 카드명을 누르면 카드 정보가 열립니다.
- 효과가 끝나면 화면 하단(폰: 전체 폭 시트)에 **효과 처리 카드**(출처 카드, 인쇄 효과문, 결과 목록, 메모리 변화)가 뜨고, 연쇄는 1/3 식의 이전/다음으로 넘겨 봅니다. 상대측 카드에 피해를 준 효과는 붉은 경고 배너가 붙습니다.
- 표시 시간은 카드 하단 셀렉트(짧게 2초/보통 5초/길게 10초/수동 확인, 기본 5초)로 설정하며, 자기 자신에게만 영향인 효과는 최대 2초 후 접힙니다(접히면 효과 N건 칩으로 다시 열 수 있음).
- 영향받은 카드에는 6초간 🎯 배지와 색 링, 소멸한 카드는 같은 구역에 유령 타일(눌러서 닫기)이 남습니다.
- 오른쪽 패널의 **효과 기록** 탭에 최근 50건이 최신순으로 쌓이며, 항목을 누르면 인쇄 효과문이 펼쳐집니다.
- 엔진은 그대로이며 표현만 추가됩니다(state.fxHistory, effects.js runScript / state.js fxNewRec, fxCommit). soak 등 자동 테스트는 UI에 의존하지 않습니다.

## 필드 표기 (효과가 어디서 일어나는지 필드 위에 직접 표시)

- 기본값(설정 `필드 표기: 켜기`)에서는 위의 '효과 처리 카드'(모아서 보는 요약 패널·페이저)·🎯 배지·유령 타일을 쓰지 않고, 효과 결과를 **해당 카드/구역 바로 옆**에 개별 표시합니다. 로 예전 방식으로 되돌릴 수 있습니다(localStorage `digimon_fx_field`, '효과 기록' 탭의 셀렉트).
- **출처 라벨**: 출처 카드(필드/육성/진화원 스택) 위에 핀으로 「카드명」【태그】 발동 + 인쇄 효과문 앞 40자가 소유자 색(P1 파랑/P2 주황) 테두리로 붙습니다. 필드를 떠난 출처는 트래시 칩, 옵션은 배틀 에어리어 중앙선(메모리 게이지 위)에 표시됩니다.
- **대상/결과 배지**: 디지몬에는 '+2000 DP'·'레스트'·'패로 되돌림'·'소멸 ← P2 「X」【등장 시】'(소멸은 마지막 위치에 점선 유령), 시큐리티 칩에 '−1 (파기)', 메모리 게이지에 '메모리 +2 (10→12)', 덱/패/트래시 칩에 '드로우 ±N'·'파기 +N' 등. 같은 대상에 여러 배지는 세로로 쌓입니다. 출처 라벨에서 각 대상으로 **애니메이션 화살표**(SVG, pointer-events 없음)가 이어집니다.
- **표시 시간**: '효과 표시'(읽는 시간 자동/2·5·10초) + '읽기 속도'를 따르며, 수동 확인이면 라벨의 ✕/배지를 누를 때까지 유지됩니다. 셔플처럼 필드에 나타낼 수 없는 결과만 모서리의 한 줄 토스트로 나옵니다. '효과 기록' 탭은 그대로 로그로 남습니다.
- **선택창**: 모든 선택 모달 맨 위에 '📌 P1의 「카드명」【태그】'가 뜨고, 대상 선택 중에는 후보 디지몬에 초록 링 + 출처에서 오는 초록 화살표가 필드 위에 표시됩니다.
- 구현: `src/fxfield.js`(본문 밖 `#fxf-root` 고정 오버레이, 레이아웃 이동 없음). 앵커는 타일의 data-fxp/-fxu/-fxn, `data-fxpile`, `data-fxhand`, `.mem-track`을 렌더·스크롤·리사이즈·이미지 로딩마다 다시 찾아 배치합니다. 폰(375px)에서는 작은 글씨로 표시합니다.

## 효과 발동 이펙트 (VFX)

- 효과가 발동하면 화면 중앙에 **「【등장 시】 발동! 카드명」 배너**가 스치고, 출처 카드가 제자리에서 확대되며 링·광선·불꽃 파티클이 터집니다(보드에 없는 카드는 중앙에 플립 인). 색은 태그별: 등장=금, 진화=청록, 어택=적, 소멸=보라, 시큐리티=주황, 메인/옵션=흰색, 《키워드》=녹색, 턴 시작/종료=청록(틸), 딜레이=자홍, 진화원(상속) 효과=은색.
- 결과별 연출: 소멸(적색 플래시·흔들림·파편), 패로/덱으로 되돌림(위로 스윕), DP 증감(녹색 ▲ +N / 적색 ▼ -N), 드로우·패 추가(카드가 패로 날아감), 메모리 변화(게이지 펄스 + 떠오르는 숫자), 시큐리티 파기(파일 섬광 + 금 간 카드 뒷면), 키워드·효과 부여(🛡), 레스트/액티브(회전 글로우).
- 어택/배틀은 state.log 줄을 읽어 공격자 돌진(잔상), 충돌 스파크, DP 비교 숫자, 승자 플레어를 보여줍니다.
- **설정**: 효과 처리 카드 하단과 '효과 기록' 탭의 `이펙트` 셀렉트(화려하게 / 보통 / 끄기, 기본 화려하게, localStorage `digimon_fx_vfx`). 시스템의 '동작 줄이기(prefers-reduced-motion)'가 켜져 있으면 저장값이 없을 때 끄기가 기본입니다.
- 구현: `src/fx.js`(버스 `fxEmit(kind, payload)` — main.js의 fxSync/render가 호출) + `src/fx.css`. 본문 밖 `#vfx-root` 오버레이(pointer-events:none, 보드 위·모달 아래, 배너/숫자만 모달 위)에 풀링한 DOM과 CSS transform/opacity 키프레임만 사용하고 동시 요소 수를 제한하며(폰은 파티클 절반), 엔진은 기다리지 않는 순수 표현이라 soak 등 자동 테스트와 무관합니다.

### 연출 순서(시퀀서) · 등장/진화/옵션 이펙트 · 육성 페이즈 바

- **한 줄로 진행**: 발동 배너·등장/진화/옵션 연출은 `fx.js`의 하나의 타임라인(`reserve`)에 순서대로 예약됩니다. 선택창(대상/공개/확인)은 `ctxChoose`가 `fxWhenIdle()`을 기다린 뒤에야 나타나므로 **배너 → 선택창 → 결과 카드** 순서가 됩니다. 결과 카드·보드 마커·소멸 잔상은 선택창이 열려 있거나 연출 중에는 보류되었다가 끝난 뒤 표시됩니다. 여러 효과는 하나씩(각자 배너 → 선택창). 배너를 누르면 건너뜀, 최대 약 2.8초 뒤에는 무조건 선택창이 열립니다(교착 방지). 엔진 로직은 건드리지 않습니다.
- **카드 내려놓기 이펙트**(`이펙트` 설정 준수: 끄기=없음, 보통=짧게, 화려하게=전체): 등장=패에서 떠올라 잔상을 남기며 슬롯에 착지(충격파+스파크), 진화=시안 플래시와 함께 내리꽂힘+LEVEL UP, 옵션=중앙에서 뒤집혀 빛나다 입자로 흩어진 뒤 효과 배너, 조그레스/디지크로스/버스트=합체 플래시, 시큐리티/진화원/부화=작은 배치 플래시. 배틀 로그 줄을 읽어 동작하며(`fxEmit('play'|'evolve'|'option'|'place', …)`도 사용 가능) 모바일은 입자 수를 줄입니다.
- **육성 페이즈 바**: 육성 페이즈에는 화면 하단(모바일은 하단 시트)에 `🥚 부화` / `⬆ 배틀 에어리어로 이동` / `⏭ 아무것도 안 함 → 메인 페이즈로` 큰 버튼과 사유가 표시됩니다. 데스크톱에서 Space/Enter = 아무것도 안 함. 설정 `육성 페이즈 자동 넘김`(기본 꺼짐, localStorage `digimon_breed_auto`)은 부화/이동을 마치면 바로 메인 페이즈로 넘어갑니다.

## 덱 빌더 검색·필터·미리보기

- 검색창은 이름·카드번호·특징·효과·진화원 효과·진화 조건·색 이름(옐로/퍼플 등)까지 전부 검색합니다. 공백=AND, `"구문"`, `-제외`, `a|b`(OR), 대소문자·띄어쓰기 무시. 범위 선택(전체/이름/특징/효과/진화원 효과) 가능.
- 필터 패널(접이식): 종류, 색(+단색만), Lv, 코스트/DP/진화 코스트 범위, 특징(자동완성), 키워드(《》), 효과 타입(【】), 팩/세트, 레어도, 내 덱만, 한도 찬 카드 숨기기, 정렬. 마지막 필터 상태는 localStorage에 저장됩니다.
- 카드 클릭 = 미리보기(PC 우측 패널 / 폰 하단 시트, ◀ ▶ 로 결과 넘겨보기, Esc 닫기). 타일의 ＋ 버튼, 더블클릭, 길게 누르기 = 바로 추가.
- 검색 로직은 `src/dbsearch.js`(순수 함수), 테스트: `node scripts/test-dbsearch.mjs`.

## 패러렐(대체 일러스트) 카드

- 패러렐 카드는 룰상 **같은 카드 넘버 = 같은 카드**(2-12-1)이므로 게임 로직은 일반 카드 번호만 사용하고, 패러렐은 **일러스트/레어도 변형**으로만 취급합니다. 동일 넘버 4장 제한(예외 50장 등)은 패러렐 포함 합산 그대로입니다.
- 데이터: `node scripts/build-parallels.mjs` → `data/parallels.json` (카드번호별 변형 목록, 약 400KB, 2004종). 로드 후 `S.PARALLELS`.
- 덱 빌더: 카드 미리보기의 "일러스트 선택"에서 덱에서 쓸 아트를 고르면 덱 JSON의 `art: { "BT1-009": "BT1-009_P1" }`로 저장됩니다(구버전 덱과 호환). 타일의 `🎨×N`은 패러렐 종류 수, `패러렐` 배지는 대체 아트 사용 중 표시. 필터: "패러렐 있음", 레어도 필터는 패러렐 레어도(SR/SEC 등)도 매칭.
- 게임: 시작 시 `players[p].art`에 복사되어 `S.artUrl(state, p, cardId)`로 그 플레이어의 카드 이미지만 바뀝니다. 이미지 로드 실패 시 일반 아트로 자동 대체.
- 검증: `node scripts/test-parallels.mjs`

## 덱 분석 도구 (덱 빌더 오른쪽 패널 하단)
- **📊 통계** (접이식, 열려 있는 패널만 실시간 갱신): 종류별 수, Lv 분포, 코스트 곡선(디지몬/테이머/옵션 누적), 색 분포(다색은 각 색에 중복 집계), DP 구간, 키워드·효과 타입 수, 특징 상위, 평균 코스트, 시큐리티 효과 밀도, 4장 채운 카드, 패러렐 선택 수. **진화 라인 커버리지**는 게임 엔진의 진화 조건(`canEvolveAny`: 일반 진화 + 〔진화〕 특수 라인)으로 각 디지몬이 덱 안의 어떤 카드에서 진화할 수 있는지 나열하고, 도달 불가(orphan)·Lv.3 뿌리 없음을 표시합니다.
- **🎲 샘플 핸드**: 실제 규칙대로 5장 오프닝 핸드 → 멀리건(1회) → 핸드 확정 시 시큐리티 5장(덱 위에서) → 턴마다 1장 드로우, 디지타마덱은 별도(부화 버튼). 기록 유지. **시뮬레이션**은 1천/1만/5만 회를 프레임 단위로 나눠 실행(진행 바)하며 Lv.3 보유율, 코스트≤3 디지몬 없음 확률, 블로커, 진화 라인 조각, 평균 테이머/옵션, 멀리건 개선폭, 지정 카드가 오프닝/3턴째까지 올 확률(이론값 병기)을 보여 줍니다.
- **🩺 체크업**: 규칙 위반(`deckLegality`), Lv.3 부족, 저코스트 부족, 옵션 색 조건(룰 4-22), 진화 불가(orphan), 조그레스/디지크로스/어셈블리 재료 부족, ACE 안내(룰북상 ACE 전용 장수 제한은 없음) 등을 이유와 함께 표시. 항목을 누르면 검색 결과가 관련 카드로만 필터됩니다(배너의 「해제」로 복귀).
- **🗂 덱 관리**: 저장된 덱 이름 변경/복제/삭제/▲▼ 순서 변경, 저장 덱과 현재 덱의 차이(추가/제거) 비교, 저장 덱 전체를 JSON으로 내보내기·복원(같은 이름은 덮어쓰기), 인쇄용 보기(`window.print`, 이미지 옵션). 내 덱 목록은 종류/Lv/코스트/색/이름 정렬과 카드별 ＋/－/✕(전부 제거) 버튼을 지원합니다.
- 순수 로직은 `src/decktools.js`, UI는 `src/decktools-ui.js`, 테스트는 `node scripts/test-decktools.mjs < /dev/null` (초기하분포 정확값과 몬테카를로 결과 비교 포함).

## 연습 모드 도구 (되돌리기 / 저장 / 리플레이 / 핸드 조작)
상단 바의 버튼 그룹(모바일에서는 아이콘만 표시)에서 사용합니다. 로직은 `src/snapshot.js`(스냅샷·타임라인), `src/savegame.js`(저장/불러오기), `src/replay.js`(로그 내보내기), UI는 `src/practice.js`입니다.
- **↶ 되돌리기 / ↷ 다시** (Ctrl+Z / Ctrl+Shift+Z, Ctrl+Y): 직전 "행동" 이전 상태로 복원합니다. 등장·진화·어택·옵션 사용·패스·부화/이동이 각각 한 단계이며, 그 행동이 일으킨 효과 선택창/어택 진행은 같은 단계에 포함됩니다. 스냅샷은 **안정 시점**(해결 중인 효과·선택창·어택·턴 종료 처리가 없을 때)에만 찍으므로, 그 사이에는 버튼이 비활성화되고 툴팁에 이유가 표시됩니다. 최대 50단계, 스냅샷 1회 약 0.1ms. 로그는 지우지 않고 `(되돌림)` 줄을 추가합니다. vs CPU 모드에서는 내 차례 시점으로만 되돌아갑니다.
- **💾 저장·불러오기**: 슬롯 5개(이름·시각·턴·덱 이름 표시) + 자동 저장 슬롯(턴이 바뀔 때마다 갱신). 시작 화면에 "마지막 게임 이어하기"가 나타납니다. 게임 JSON을 파일로 내보내기 / 클립보드 복사 / 붙여넣기·파일로 불러오기, 로그를 읽기 쉬운 턴별 텍스트(.txt)와 JSON으로 내보내기를 지원합니다. 저장은 안정 시점에서만 가능합니다. "이 턴 종료 시" 예약 효과는 종류별 `desc`로 복원되며, 복원할 수 없는 예약은 불러올 때 알림과 함께 제외됩니다.
- **▶ 리플레이**: 지금까지의 안정 시점 스냅샷을 이전/다음/슬라이더(←/→ 키)로 넘겨 보며 스텝별 로그를 확인합니다. "여기서 이어하기"로 그 시점부터 다시 진행할 수 있습니다(최대 600스텝 기록).
- **🎲 시작 핸드 다시 뽑기**: 같은 덱으로 새로 셔플해 오프닝 핸드/멀리건부터 재시작합니다(멀리건 화면에도 버튼 있음).
- **🛠 핸드 조작** (연습용 치트, 기본 접힘): 카드를 아무 영역 사이로 이동/생성, 메모리 설정, 스택 DP±1000·레스트 토글·진화원 제거. 모든 조작은 로그에 `(연습용 치트)`로 남고 되돌릴 수 있습니다.
- 검증: `node scripts/test-snapshot.mjs [게임수]` — 랜덤 플레이 중 스냅샷→복원 동일성, 복원 후 같은 선택으로 진행했을 때의 동일한 결과, JSON 왕복을 확인합니다.

## CPU 대전 (혼자 연습하기)
시작 화면의 **대전 방식**에서 `CPU 대전`을 고르고 **CPU 강도**(쉬움 / 보통 / 어려움)를 정하면 P2를 컴퓨터가 조작합니다. 선택은 브라우저(localStorage `digimon_cpu_cfg_v1`)에 저장되고, 저장/이어하기/되돌리기 후에도 CPU 모드가 유지됩니다(게임 상태의 `vsCpu` 플래그).
- **화면**: CPU의 패는 뒷면으로 가려지고(`CPU 패 보기` 체크로 공개), 상단 `🤖 CPU 생각 중…` 바에서 **일시정지/재개**와 **속도(빠르게/보통/느리게)**를 바꿀 수 있습니다. CPU의 행동은 로그에 `🤖 CPU: …`로 남고, 효과 처리 카드/이펙트 연출은 사람 차례와 똑같이 재생됩니다(이펙트가 끝난 뒤에만 다음 행동, 행동 사이 약 0.7~1초).
- **입력 잠금**: CPU 차례에는 사람이 P2 카드를 끌거나 패스/다음 페이즈를 누를 수 없습니다. 반대로 CPU가 어택하면 **블록·카운터·대상 변경·【시큐리티】 효과·대체 효과 선택 등 P1 소유의 선택은 그대로 사람에게** 뜨고, P2 소유의 선택(사람 차례의 블록/카운터 포함)은 CPU가 자동 응답합니다. 선택창(`ctx.choose`)의 소유자는 `deciderFor`가 종류·발동 중인 효과의 주인으로 판별합니다.
- **멀리건**: CPU는 Lv3 저코스트(≤3) 디지몬이 있거나 Lv3가 2장 이상이면 유지, 아니면 멀리건(어려움은 Lv4/테이머가 함께 있으면 코스트 5 이하 Lv3 한 장도 유지).
- **강도**
  - 쉬움: 합법적인 행동 중 무작위 선택(부화/이동/등장/진화는 하되 어택·블록은 절반 이하 확률, 카운터 거의 안 씀).
  - 보통: 그리디 가치 평가 — 진화(드로우 보너스 포함)/등장/옵션(제거·드로우·회복·메모리 등 효과 종류별 가치)을 점수화하고, **메모리 관리**(패스는 상대에게 메모리 3을 주므로 3 이하로만 넘기는 행동은 공짜로 취급, 그 이상은 감점), 어택은 DP·블로커·시큐리티 잔량으로 기대값 계산, 블록은 이기는/동점 블로커와 치명타 방어 위주.
  - 어려움: 보통 + 치명타 탐지(시큐리티 잔량·S어택·상대 블로커 수, 블로커 미끼 순서), 더 공격적인 어택, 시큐리티가 적을 때 블로커를 아끼는 위협 평가, 낮은 시큐리티에서 카운터/희생 블록.
  - 상태 복제 기반 1~2수 탐색은 하지 않습니다(카드 효과가 모듈 전역 레지스트리를 쓰므로 정확한 복제가 어렵다) — 대신 어택 시퀀스를 숫자로 근사하는 추상 모델을 씁니다.
- **사람 대전 편의(플레이 피드백 반영, 자세한 목록은 `docs/cpu-play-feedback.md`)**
  - **CPU 최근 행동 줄**: CPU 상태 바 아래에 `방금 CPU: …`(상대 차례) / `직전 CPU 턴(N): …`(내 차례)가 항상 표시되고, 그 턴의 행동 요약(`부화 → 이동 → 등장 → 어택`)과 가장 최근 로그 한 줄이 붙습니다. 부화·이동·트레이닝·【메인】도 기록됩니다.
  - **내 핸드 사용 가능 표시**(내 메인 페이즈, 양쪽 모드 공통): 초록=지금 낼 수 있음(코스트 ≤ 내 남은 메모리), 파랑=진화 가능, 노랑=낼 수는 있지만 메모리가 넘어가 턴이 넘어감, 흐림=불가. 카드에 마우스를 올리면 이유가 툴팁으로 나옵니다.
  - **패스 실수 방지(CPU 대전)**: 낼 수 있는 카드가 남은 채 `패스`를 누르면 버튼이 `⚠ 지금 낼 수 있는 카드 N장 — 한 번 더 누르면 패스`로 바뀌고(4초), 그 안에 다시 누르면 패스합니다.
  - **종료 화면**: 승/패 문구와 사유(예: 시큐리티 0에서 피격), 마지막 보드(CPU 패 공개), `🔁 같은 덱으로 재대전` / `새 게임 (덱 선택으로)` 버튼.
  - **백그라운드 탭**: 탭이 숨겨진 동안 워치독은 정체로 보지 않으며, 돌아오면 CPU가 즉시 이어서 진행합니다. 자동 처리되지 않고 12초 넘게 멈춘 효과는 재시도 → 수동 종료 순으로 복구합니다.
- **견고함**: 모든 행동은 UI와 같은 함수(`doPlayFromHand`/`doEvolve`/`runJogress`/`attackFlow`와 어택 단계 함수 `pa*`, `S.hatchDigitama`, `E.declarePass` …)로 수행하고, 상태가 바뀌지 않으면 그 행동을 그 턴에는 금지합니다. 예외는 잡아서 로그로 남기고 다음 행동으로 넘어가며, 22초 넘게 CPU 차례가 진행되지 않으면 워치독이 패스/첫 선택지로 강제 복구합니다(턴당 행동 45회 상한).
- **구조**: `src/cpu.js`(판단 + UI 드라이버), `src/main.js`의 `vs CPU` 구역(설정·입력 잠금·선택창 라우팅·`cpuApiObj`), `scripts/test-cpu.mjs`(헤드리스 검증).
- **검증**: `node scripts/test-cpu.mjs [게임수=40] [--random-decks] [--only=hard-easy] [--tune=키:값,…] < /dev/null` — 실제 엔진으로 CPU끼리 전 판을 두어(양쪽 자리·덱 교대) 예외/정체 0건과 강도별 승률을 확인합니다. 300판 기준 어려움 vs 쉬움 약 94%, 보통 vs 쉬움 약 93%, 어려움 vs 보통 약 55~59%(오차 ±3%p).

## 자동 검증 (soak / fuzz / test-all)
- `node scripts/test-all.mjs < /dev/null` — 문법 검사, `scripts/test-*.mjs` 전부, `audit-effects`(커버리지 100% 기대), `soak 60`, `fuzz 200`을 차례로 돌리고 한 페이지 요약과 종료 코드(0=전부 통과)를 출력합니다. `--quick`은 축소판.
- `node scripts/soak.mjs [게임수] < /dev/null` — 무작위 플레이 + 예외/기본 구조 불변식(기존 스크립트, 그대로 유지).
- `node scripts/fuzz.mjs [게임수] [--gen random|theme|mech|starter|mix] [--seed N] [--minutes M] [--json out.json] [--logn 30] [--dumpwin] < /dev/null` — 더 강한 불변식 퍼저.
  - **카드 보존 불변식**: 매 행동 뒤 플레이어별 카드 id 멀티셋(덱+패+트래시+시큐리티+디지타마 덱+육성/배틀 스택의 맨 위·진화원·링크 카드+그 밖의 카드 배열)이 시작 시점과 같은지 검사(토큰 제외). 분실 / 복제 / 소유자 뒤바뀜을 행동·발동 효과 카드와 함께 보고합니다.
  - 구조 불변식: 스택 uid 유일성, 알 수 없는 카드 id, 진화원 문자열, keywords 값, 메모리 범위, NaN/Infinity(상태 전체)와 음수 만료값, pending 정체(40행동 초과 미해결/500 초과), 턴 정체(18-3 루프), 승자 일관성, 로그의 `undefined`/`NaN`/`[object`.
  - 드라이버: 등장(디지크로스·어셈블리 포함)/옵션/진화(일반·버스트·어플 합체)/조그레스/링크/【메인】·[패]【메인】·딜레이·트레이닝/어택(카운터·블록·시큐리티 체크·관통·효과로 시작한 어택)을 UI(main.js)와 같은 S.* 호출로 수행하고, 선택 응답은 취소·부분 선택을 섞어 무작위로 고릅니다.
  - 덱 생성기: `random`(균일), `theme`(색+특징 클러스터를 진화 그래프 canEvolveAny로 따라 걷기), `mech`(조그레스/디지크로스/버스트/어플/링크/어셈블리/블래스트/ACE/세이브/시큐리티/딜레이/오픈 등 키워드 스택), `starter`(ST1~ST24 짝짓기). 게임마다 시드가 출력되어 `--seed <시드> 1 --gen <종류>`로 재현됩니다.
